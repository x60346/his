# 與 jian-HIS 的比較，以及各角色實際使用的檢視

> 2026-11-11。比較對象：C:\work\jian-HIS（正式上線的前端，Vue/Quasar，847 個 .vue；規則在看不到的後端）與本專案。
> 方法：五個面向（掛號批價、門診與預防保健、藥局庫存、住院護理、系統管理）分別逐檔閱讀兩邊程式，再由我在程式碼或畫面上複查重要項目。
> 每一項標註驗證程度：**畫面確認**（在瀏覽器上操作看到）、**程式確認**（我讀了相關程式碼確認邏輯）、**讀程式碼推得**（比對時讀到、尚未逐一複查）。
> jian-HIS 不一定比較好，以下也列出本專案做得比較好的地方。

## 一、先回答：為什麼掛號時不收錢、也不顯示金額

**jian-HIS 的做法**（`booking/components/BookingEditItem.vue:811-917`）：掛號表單有一區「應付金額」——掛號費（依身分）、部分負擔（向後端查）、掛號優免、欠卡押金、累計應繳、累計欠款，以及付款方式與實付。實付預設 0，也就是**可以先收、也可以不收**；批價時扣掉已收的，只收差額，還可以「欠繳」（`charge/components/PayTheCheckEditItem.vue`）。掛號後沒繳的，「掛號查詢」有「繳費」按鈕補收（`DialogPay.vue`）。

**本專案的做法**：掛號只建立掛號紀錄；掛號費和部分負擔一律在「批價結帳」一次算、一次收、開一張收據（`services/billing.ts` 第一行就是掛號費）。

**當初為什麼這樣取捨**
- 一個收錢的地方、一張收據：金額只有一個來源，日結對帳簡單；不會有「掛號收了 150、批價又算一次」的重複或漏扣。
- 先收再補差額，就必須有「預收款／欠款帳」——誰預付了多少、退掛要退多少、欠的錢下次來要提醒。這是一套獨立的帳務，當時展示系統沒做（之後補上：欠款 aa14c17、掛號預收見下方第六節）。
- 大醫院線上預約的病人本來就不在掛號櫃台付錢，「看完診一次結清」兩種情況都適用。

**但這個取捨有一部分是錯的**：不在掛號時收錢可以接受，**不顯示要收多少**就沒有理由——櫃台常被問「今天要多少錢」，而掛號費只出現在系統管理的收費設定裡，櫃台根本看不到。這屬於下面「使用者需求」的問題，應該修。

## 四、jian-HIS 有、本專案沒有的功能

### 值得做（屬於核心流程，展示時會被問到）
- **掛號**：顯示應收金額、修改轉掛（改期換診）、更正身分、報到與過號狀態、掛號單列印、看診進度
- **批價**：欠款與分次付、優免、日結的未收清單與收費人員別
- **門診**：組套與常用處方、完整的「同前次」、預設天數批次套用
- **藥局**：慢性處方箋領藥（門診藥局量最大的一群）、領藥號搜尋
- **住院**：護理端的有效醫囑清單、全病房待辦、新醫囑提示、出院時列出未執行項目

### 做法不同、各有道理
- 藥品庫存：jian-HIS 是藥庫／藥房兩層、採購單、盤點單；本專案原本是單一庫存＋異動帳＋FEFO 自動扣批號。✅（c7f8252）改為「依醫院規模」：小型單一藥局、大型藥庫＋門診藥局＋住院藥局，批號與異動帳都帶地點（重建展示資料時選）。盤點單 ✅（9c473f9）盲盤、清點期間照常發藥、另一人覆核過帳；採購單 ✅（f0cd6e8）開單與核准分開、對品項分批到貨、補貨申請轉採購、無單進貨要原因；供應商主檔 ✅（a3a2ab0）統編檢查碼、只能選往來中的、停用前檢查進行中的單、以前的進價與比價；撥補單 ✅（16c83ee）藥局請領 → 藥庫撥發（運送中）→ 藥局逐批簽收（短少寫原因），退回藥庫 ✅（0e566b3）藥局逐批退、藥庫簽收、各地點安全庫存可改、補貨申請在大型醫院由撥補滿足。住院給藥 ✅（09474dd）改為 UD：住院藥局每日調劑次日、補調劑當天，護理師只能給已調劑的，沒給的退藥點收；✅ a996680 調劑與核對兩段（核對才扣帳、可退回重調、共用雙人核對設定）、護理站送回藥局後藥師才能點收；PRN、STAT 用病房常備、給藥時扣。
- 排班：jian-HIS 每週逐週排、可複製上週；本專案用每週範本自動展開，並有停診代診與影響分析。

### 不在展示範圍
健保 IC 卡讀寫與每日上傳、門住診申報與抽審、Tw-DRGs、急診、居家照護、檢驗檢體與影像（PACS）、手術室、疫苗、成人健檢與新生兒、慢性病個案追蹤、KPI、多機構、印表機管理、衛材庫、伙食。這些需要硬體、政府介面或整個獨立的業務，展示系統做了也只是空殼。

## 五、本專案刻意不同、或比 jian-HIS 好的地方

| 項目 | 本專案 | jian-HIS |
|---|---|---|
| 權限 | 選單、路由守衛、服務層用同一套判斷，每個寫入都再檢查角色 | 權限只用來藏選單，路由檢查被註解掉，知道網址就能進 |
| 過敏 | 依藥物類別比對學名，病人列直接寫出過敏原 | 只比對院內代碼，病人列只寫「有過敏」 |
| 劑量 | 依常用劑量倍數分「需確認」和「直接擋」 | 前端沒看到 |
| 給藥時間窗 | 太早給由服務層擋下，逾時即時標示 | 可選任何過去時間執行 |
| 效期 | 近效期與待報廢標籤、一鍵報廢、過期不計可用量 | 前端沒看到提醒 |
| 高警訊藥品 | 主檔標記，處方、調劑、藥袋都標示 | 主檔沒有這個欄位 |
| 停診 | 先列影響、代診或停診、通知名單追蹤 | 前端沒有停診與通知 |
| 刪除 | 被引用過的只能停用 | 列表有「刪除」按鈕 |
| 收費設定 | 修改前試算、告知受影響的待批價筆數 | 有生效日（本專案：藥價有生效日、批價依看診日 ✅（db3e4e5）；醫令點數、掛號費、部分負擔也有生效日 ✅（860020d），和藥價同一套 dated-rules） |
| 首頁 | 依角色列待辦 | 只有模組圖示 |

**取捨：雙人核對**（U24）——本專案把調劑拆成核對、發藥兩步，但不強制兩個人。許多診所只有一位藥師，強制兩人會讓單人藥局無法發藥，所以做成「可設定」：管理員開啟後，核對的藥師不能自己發藥（預設關閉）。

1. **先修程式錯誤** B1–B6（交班跨夜、身分無法更正、過號循環、異常門檻、藥局跨日、案件分類）——都是小改動，而且是錯，不是取捨。
