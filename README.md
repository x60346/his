# HIS 展示系統

醫院資訊系統（Hospital Information System）的**前端展示版**。不串接後端，所有資料由瀏覽器內的模擬層產生與保存，打開就能完整操作門診、住院、藥局、護理、預防保健與系統管理。

> 所有病人、醫師、病歷皆為虛構。這是教學與展示用的系統，**不可用於真實醫療情境**（見文末〈已知的簡化與限制〉）。

技術：Vue 3、TypeScript、Pinia、Vue Router、Tailwind CSS、Vite。不使用 UI 套件，所有元件自行實作。

**線上展示：https://x60346.github.io/his/**（每次推送到 `main`，GitHub Actions 會先跑流程測試與建置，通過後自動部署，見 `.github/workflows/deploy.yml`）

## 快速開始

需要 Node.js 18 以上。

```bash
npm install
npm run dev          # 開發伺服器 http://localhost:5180
```

| 指令 | 用途 |
|---|---|
| `npm run dev` | 開發模式 |
| `npm run build` | 型別檢查 + 正式建置（輸出到 `dist/`，可放在任何靜態主機或子目錄） |
| `npm run preview` | 預覽建置結果 |
| `npm run typecheck` | 只做型別檢查 |
| `npm run smoke` | 流程測試：在 Node 中直接呼叫服務層，跑完整就醫流程與各項規則（2467 項） |

### 展示帳號

密碼皆為 `1234`，登入頁右側可直接點選帳號快速登入。右上角「變更密碼」改過的帳號，快速登入只帶入帳號（標「已改密碼」），「重置展示資料」可還原。

| 角色 | 帳號 | 可以做的事 |
|---|---|---|
| 系統管理員 | `admin` | 檢視所有頁面；「經營月報」；帳號、權限（在規則內調整，可指定給個人；示範：`clerk02` 被指定「優免核准」）、科別醫師、排班、收費、主檔、稽核、展示資料。**不能執行臨床操作** |
| 醫師 | `dr01` – `dr12` | 門診看診、住院醫囑、病程紀錄、預防保健（`dr12` 是急診醫師：在「門診看診」的急診診次看急診病人，在「急診」決定去向、結束留觀） |
| 護理師 | `nurse01`、`nurse02` | 掛號、住院報到、護理站（給藥、生命徵象、護理紀錄、交班、術前準備）、手術室（排程、三段安全查核；`nurse02` 被指定「手術排程」）、預防保健 |
| 藥師 | `ph01`、`ph02` | 門診調劑發藥、補貨申請、藥品庫存（採購單開單與到貨入庫、無單進貨、盤點單、報廢）；盤點單由沒清點的另一位藥師（或管理員）覆核；報廢要另一位藥師（或管理員）當場覆核 |
| 掛號批價 | `clerk01` | 掛號、病患資料（含病歷影本申請）、批價收費、住院報到（`clerk02` 是櫃台組長：可核准優免；`clerk03` 是長期沒登入、密碼過期太久**已鎖定**的示範帳號——登入看鎖定訊息，`admin` 在「帳號」按「重設密碼」解鎖） |
| 感染科醫師 | `dr11` | 「抗生素審核」：管制性抗生素（Vancomycin、Meropenem、Piperacillin/Tazobactam）先用後審，開立後 48 小時內核准（給天數）或不核准（寫建議）。不看門診 |
| 醫檢師 | `lab01` | 檢驗：門診批價後、住院採檢後的檢驗逐項登打結果、發報告；已發出的只能更正（寫原因、留舊值）。「血庫」：備血單驗血型、交叉試驗配血、發血；血袋入庫、報廢 |
| 營養師 | `diet01` | 「營養」：營養篩檢 ≥3 分的住院病人寫營養評估與建議（不開醫囑，主治已閱）；送餐清單 |
| 放射科醫師 | `dr10` | 「影像判讀」：X 光、超音波、電腦斷層寫報告（所見、結論；可帶入正常範本），有重要發現勾起來；發出後只能補充。不看門診（`dr10` 也是醫師帳號，選單和其他醫師一樣） |
| 護理師＋掛號批價 | `staff01` | 多角色帳號（小診所跟診兼櫃台）：登入時選角色，右上角切換 |

### 展示資料

- 第一次開啟時自動產生，**以「今天」為基準**：今日候診、住院第幾天、給藥排程都和當下時間連動。
- **今天走到哪一步，看建立資料時是幾點**：上午 07:30 起掛號、08:30 起叫號，下午 13:00 起掛號、13:30 起叫號，每位約 12 分鐘；時間還沒到的步驟就還沒發生。清晨建立的資料像真正的一天開始——今天的掛號都是前幾天預約的、還沒有人看過診；要看完整的「忙碌的一天」（待批價、待領藥都有），請在上午十點後按「重置展示資料」。
- 隔天再開會提示資料已過期，可一鍵「重置為今天」（系統管理 → 展示資料，或頂端提示列）。
- 可匯出成 JSON，在其他電腦匯入，重現同樣的展示情境。

## 建議的展示路線

**門診（約 5 分鐘）**

1. `clerk01`「掛號作業」：搜尋病人 → 選診次 → 掛號（可勾「掛號時預收」先收一筆，批價時扣抵、多退少補；退掛當場退還）。確認區顯示預估應收；符合資格的預防保健項目可一併勾選。今天的現場掛號預設「同時報到」；電話預約取消勾選，病人到院時在清單或病人卡上按「報到」（下午家醫科 1 號是前兩天預約、還沒到的示範病人）。病人卡上的預約可直接退掛或改期；診次卡的「名單」看該診有誰。
2. 該診的醫師（例如家醫科 `dr01`）「門診看診」：叫號（未報到的病人會先確認）→ 看診頁由上而下依 S→O→A→P 排列（頂端有前次就診摘要：「同前次」帶入診斷、藥品、處置、評估與計畫，或「只帶處方」），在醫令段套用組套（例：「上呼吸道感染」；內科 `dr02`、`dr03` 另有共用的「糖尿病追蹤」）→ 完成看診；S／O／A／P 輸入「.簡碼」再按空白鍵展開片語（`dr01`：`.uri`、`.wnl`、`.fu`）；「完成並叫下一位」（Ctrl+Enter）一次叫好下一號。病人上方「回診」列按「預約回診」：快速選 1／2／4 週後（慢性病連續處方另有「處方用完前」），系統找好最近一個可掛的自己的門診，也可選日期挑同科的診；約好就是正式掛號、接著印預約回診單，櫃台掛號清單標「醫師預約」。這一科已有未來掛號的，要勾「仍要再約一次」。開到過敏藥物會跳警示；掛了預防保健的病人可直接在看診頁登錄，本次量的血壓身高體重會帶入。開第一～三級管制藥（例：搜尋「嗎啡錠」＝Morphine 15mg 錠，第二級）時藥品上方標「需專用處方箋」，完成看診後跳出**管制藥品專用處方箋**（病人身分證號、地址、總量國字大寫、醫師的管制藥品使用執照號碼）可列印；醫師沒有使用執照（`dr08`）或已過期（`dr09`）就開不出來。
   - **急診**：`nurse01`「急診」→「檢傷掛號」：找病人 → 主訴（常見主訴一鍵帶入）＋生命徵象 → 即時建議級數（主訴預設級數與生命徵象取嚴重的，例：血氧 88% → 2 級；不能選比建議輕的，比建議重要寫調升原因）→ 掛急診（急診診次、案件 E1、直接報到）。看板：待看診依級數排，等候超過目標（1 級立即、2 級 10 分、3 級 30 分、4 級 60 分、5 級 120 分）標紅，候診中可「重新檢傷」（舊級數留著）。`dr12`「門診看診」：今天的急診診次依級數排（「下一位」先叫最危急的），清單與病人資訊標檢傷級數與主訴，照門診一樣寫病歷開藥；看完回「急診」→「決定去向」：離院（批價、領藥照門診流程）、收住院（科別、主治、入院診斷 → 建今天的住院預約，住院中心待報到清單標「急診待床」排最前面，看板標「待床」等了多久；報到後變「已住院」）、轉院（醫院、原因）。批價：急診診察費取代門診診察費、急診部分負擔依檢傷級數（1、2 級一個金額，3–5 級一個金額，收費設定可調、有生效日；榮民等免部分負擔身分不收）、到院滿 6 小時每 6 小時一單位觀察床費。首頁：急診待看診（逾時）、急診待決定去向（急診醫師）、急診收住院待床。示範資料：今天急診 4 位候診（胸痛 2 級已等超過 10 分、腹痛 3 級、撕裂傷 4 級已等超過 60 分、喉嚨痛 5 級）。掛號頁不再提供 E1 案件（急診由護理師檢傷掛號）。
   - **急診留觀**（留觀＝特別的住院）：`dr12` 決定去向選「留觀」（診斷預設看診的主診斷）→ 看板「待排留觀床」、`nurse01` 首頁「急診待排留觀床」→「排留觀床」選 OB1–OB6（急診留觀區，住院中心不能拿來報到）→ 產生住院號、印腕帶 → `dr12`「留觀醫囑」到住院醫囑頁開醫囑，護理師按「護理站」直接到「急診留觀區」給藥、量生命徵象、寫護理紀錄（留觀中不顯示住院費用、不能寫出院病摘或辦出院）。看板標床號與留觀時數，超過 24 小時標紅、超過 48 小時列急診醫師首頁待辦。`dr12`「結束留觀」：離院、轉院（醫囑停止、逾時沒給的藥標暫停、留觀床清潔中；急診與留觀期間的藥、檢驗處置一起到批價結，觀察床費算到結束留觀）；收住院（科別、主治、診斷，可一併選病房的空床——同一筆住院直接轉成一般住院，住院號與腕帶不變、醫囑延續；沒選床就留在留觀床，看板「待床」、住院中心「急診留觀收住院・待轉床」按「轉床」）。收住院（直接或留觀後）的急診費用不在批價結，整筆併入住院帳單「急診」一段（不收急診部分負擔、藥品部分負擔，健保點數一起算住院部分負擔；住院從結束留觀那天起算）。急診開的藥照樣由門診藥局調劑。留觀床清潔完成：護理師在急診看板、住院中心「急診留觀區」分頁都能按。示範資料：腹痛病人 27 小時前到院、在 OB1 留觀約 26 小時（標紅）。
   - **手術排程與術前核對**：主治在住院醫囑「手術」分頁「申請手術」（術式、左右側、麻醉方式、預計日期、預估時間、術前診斷）→ 選單「手術室」（護理師、醫師）：待排程清單，有「手術排程」權限的人排手術房與時間（同房撞期、超過 08:00–20:00、排在過去都擋，可改期）→ 護理站病人「手術」分頁逐項記錄術前準備（同意書不能免；禁食、部位標記、備血、預防性抗生素可寫「不需要」的原因；備血要連這次住院的備血單、抗生素要連這次住院的抗生素醫囑）→「送手術室」（準備沒完成不能送）→ 手術室點那一台：病人的過敏、隔離、DNR 都在上面，麻醉前查核（項目全勾）→ 劃刀前暫停確認 →「開始手術」（沒做暫停確認按不了，服務層也擋）→ 離開前查核＋紗布器械術前術後計數（不符要寫原因與處理，主刀的手術紀錄與手術分頁看得到）→ 完成。主刀首頁「手術紀錄待寫」，寫術式、術中發現、失血量。做完的手術：術式＋麻醉費（依麻醉方式，局部麻醉不另收）列入住院帳單；病人在手術室不能辦出院，出院時還沒進手術室的自動取消。首頁：手術待排程、術前準備未完成（今明兩天）。示範資料：骨折病人明天 09:00 OR1 開放性復位術（準備還差禁食、部位標記、抗生素）；闌尾炎病人今天 15:00（重建時已過 13:00 就是明天 13:00）OR2 腹腔鏡闌尾切除術，準備都好了，可以直接送手術室走完三段查核。
   - **經營月報**：`admin`「經營月報」（選單「系統」；權限「經營月報」預設只有管理員，可在權限設定指定給院長、主任個人，沒權限的人選單看不到、網址進去是「沒有權限」）：選月份（本月算到今天）→ 門診（人次、初診、複診）、住院（入出院、住院人日、佔床率、平均住院天數）、收入（實收和收費報表的日結同一份計算；門診、住院、其他〔病歷影本〕應收；健保點數；藥費占比）、醫療服務量（門診處方、檢驗、影像報告），每項和上個月、去年同月比較（比率類用「百分點」；沒有資料寫「—」）；近 12 個月門診人次、實收、佔床率長條圖；門診科別（占比）、醫師、住院科別；「匯出 Excel」五張工作表（摘要、門診科別、門診醫師、住院科別、近 12 個月）。示範資料只有最近幾個月、越近越密，所以「比上月」增幅很大、去年同月都是「—」；示範資料有幾位病人最近兩個月才第一次來（初診：九月、十月），本月的初診要櫃台新建檔掛號才有。
   - **病歷影本申請**：`clerk01`「病患資料」選病人 →「病歷影本」分頁 →「新申請」：本人（姓名、身分證號要和病人資料一樣）或代理人（身分證號、和病人的關係、勾「已核對委託書」；不能填病人自己的證號）、用途；勾要影印的紀錄（完成的門診病歷、醫師已簽的出院病摘、檢驗與影像報告，可依種類篩選、全選），即時算出應收（基本費＋每頁，單價在主檔「病歷影本基本費」「病歷影本（每頁）」，可排生效日）→「收費並列印」：開收據（自費、不申報健保）、日結列在「病歷影本」，直接跳出影本（每項一頁，頁首申請單號與第幾頁、斜向浮水印「影本」，頁尾申請人與用途）。申請紀錄可補印（記第幾次、寫稽核）、當天作廢（收據一起作廢；隔天以後不行）。權限「病歷影本申請」預設櫃台，可只指定給病歷組的人。
   - **輸血備血**：醫師在住院醫囑「輸血」分頁「開備血單」（紅血球、新鮮冷凍血漿、血小板；單位數、適應症、急件）；最近的 Hb 高於 8、PLT 高於 50，或 72 小時內沒有這項檢驗，要寫輸血理由（只提醒不擋）。`lab01`「血庫」：首頁「備血待處理」→ 每張單重新驗血型（和本院上次驗的不同會擋下：可能抽錯人的血，請重抽；和病人自述的不同只提醒）→「交叉試驗配血」只列相容、沒過期的血袋（同型、先到期的在前）→「發血」；發血後 30 分鐘內還沒開始輸可以「退回血庫」，超過只能報廢。護理站選病人「輸血」分頁：已發血的那袋「開始輸血」→ 掃腕帶、掃血袋（不符當場大紅字，示範有模擬掃描）、輸血前生命徵象 → 另一位護理師或醫師輸入自己的帳密核對 → 開始；15 分鐘後量生命徵象（逾時標紅、首頁「輸血待處理」）、「結束輸血」寫輸入量；「輸血反應」勾症狀立刻停止（護理站病房清單標「已發血」「輸血中」，15 分鐘該量時標紅，本班待辦也列出、點了直接到「輸血」分頁），主治首頁與住院醫囑頁紅條「輸血反應待確認」，寫處置後解除。帳單：交叉試驗每袋、血品發出才計（退回的不算）。有血袋已發出還沒輸完不能辦出院；出院時還在血庫的配血自動釋出。示範資料：何麗華（Hb 6.8）紅血球 2 單位，一袋昨天輸完、一袋配好待發血；董雅惠（敗血症）新鮮冷凍血漿 2 單位待驗血型（入院太晚的日子沒有）。

   - **交互作用與重複用藥**：`dr01` 叫號下午診的曾秀英（骨科開的 Celecoxib、Diclofenac 還在用），處方加 Ibuprofen、Warfarin → 處方表上方即時列出提醒：「嚴重」Warfarin＋Ibuprofen／Celecoxib（出血）、「注意」同類 NSAIDs 重複，寫出哪一科哪天開的、藥還有幾天。完成看診時逐項確認，嚴重的要寫原因才能開；原因存進病歷、寫稽核，藥局調劑畫面看得到。住院「新增醫囑」同樣和執行中的給藥醫囑比（例：`dr02` 替正在吃 Aspirin 的簡淑惠開 Warfarin），住院藥局調劑清單標出。
   - **診斷證明書**：叫號後病人上方「診斷證明書」按「開立」（病名帶這次的診斷，寫醫師囑言、用途、份數）→ 證明書費（自費 × 份數）自動加進這次帳單，標「待批價收費」；收費前可修改、作廢（費用一併取消），收費後只能「作廢重開」（換字號、不另收費）。櫃台批價後收據上方列出證明書，按「列印」出 A4 證明書（印幾份＝份數）。住院在「住院醫囑」的「出院病摘」分頁開（自動帶住院期間），費用進住院帳單，出院結帳後在住院結帳頁印。
3. `clerk01`「批價結帳」：清單上就看得到預估應收 → 收款 → 印收據。身分選錯可在收費前更正。錢不夠時勾「差額記為欠款」並寫原因，照常結帳領藥；舊欠款在批價頁列出、可分次收回（掛號頁只提醒，不擋掛號；示範病人：林俊傑 100005）。「日結報表」列出看完診還沒批價的病人，實收＝應收 − 新欠 ＋ 收回；按「本月」「上月」「今年」看區間報表（最長一年；兩個月以內依日期小計，更長依月份小計），「匯出 Excel」（明細、合計、每日小計分開工作表，金額是數字可直接加總）；要匯入其他系統用旁邊的「CSV」。優免選「專案減免」要填原因並**主管核准**：按「當場核准」，由 `clerk02` 輸入自己的帳密（打錯會寫進稽核；不能是結帳的櫃台本人），或按「送簽」先結其他病人——`clerk02` 首頁出現「待核准優免」，直接核准或退回（寫原因），回到這位病人時類別與原因自動帶入，核准了就能結帳（當天有效）；收據印出核准人。已批價的收據下方列出檢驗、處置：病人沒做就離開的按「未執行」寫原因，收據上方出現待退費（健保項目通常只更正申報點數、自費的退錢）。
   - **慢箋領藥**（不看診）：病人卡片上列出慢性病連續處方箋與可領期間，按「登記領藥」→ 直接到批價（不收掛號費、診察費、部分負擔，通常 0 元）→ 藥局。示範病人：周婉婷 100020（今天可領第 2 次）。
4. `ph01`「門診藥局」：輸入領藥號按 Enter → 核對處方 → 發藥（依效期先後扣庫存）→ 列印藥袋。有第一～三級管制藥的單標「管制藥專用處方箋」（可看、可印），發藥時另外輸入領藥人的身分證號（本人要和病人資料相同；代領填代領人的），記進管制藥簿冊；「藥品庫存 → 管制藥申報」選月份或年度，列出每種管制藥各地點與全院的期初、收入、支出、期末，可匯出 Excel。前幾天沒領的單會帶到今天的清單。病人拿藥回來：「已發藥」那張按「退藥」，逐項填這次退多少（可只退一部分、可分次；已拆封的勾「不可再用」，退回後直接報廢，要 `ph02` 覆核）；只退一部分時，`clerk01` 批價頁最上面出現「待退費（部分退藥、未執行）」，按「退費」退差額（部分負擔沒變就只更正申報點數）。
5. `lab01`「檢驗」：左邊「待檢驗」列出已批價的門診檢驗與護理師已採檢的住院檢驗（舊的在前；還沒採檢的灰色「待採檢」），點一筆逐項登打——輸入時就標出偏高 ↑、偏低 ↓、危急（依病人性別的參考範圍），沒填好的一次標紅；按「發報告」。有危急值的，開立醫師（住院另含主治）首頁出現「待確認的檢驗報告」、看診頁與住院醫囑頁病人上方出現紅條，醫師按「已知悉」記下時間。「已報告」可以「更正」（寫原因，舊值留著，醫師要重新確認）。醫師在看診頁「檢驗報告」、住院醫囑頁「檢驗」分頁看各項的趨勢（最近 6 次）與每份報告。種子已有兩份危急值待確認（一位門診醫師的、`dr02` 的住院病人昨天 CBC 血色素 6.8）。
6. `dr10`（放射科）「影像判讀」：待判讀列出已批價的門診影像與護理師已執行的住院影像，左邊附臨床資訊（診斷）；「帶入正常範本」再修改「所見」「結論」，有重要發現（氣胸、腦出血…）勾起來 → 發報告。**心電圖由開立醫師自己判讀**：開了心電圖的醫師在「影像判讀」頁、或看診頁「影像報告」分頁按「判讀」。發出後原文不能改，只能「補充報告」，開立醫師要重新確認。重要發現和補充過的報告，開立醫師（住院含主治）首頁「待確認的報告」、看診頁與住院醫囑頁病人上方紅條提醒，按「已知悉」。種子已有一份待確認：`dr03` 的住院病人羅志偉昨天胸部 X 光「左側氣胸」（病人依示範日期可能不同）。

**住院（約 5 分鐘）**

1. `nurse01`「住院中心」：待報到病人 → 報到配床（符合床等的空床會亮起）。
2. 主治醫師「住院醫囑」：開立長期或臨時醫囑。長期給藥醫囑會自動產生給藥排程，高警訊藥品需再確認。口服藥的給藥時間依服用時機對齊病房用餐（飯前 07:00、飯後 08:00…），可為這筆醫囑另外指定時機，對話框下方預覽每天幾點給。示範：糖尿病病人的 Metformin 醫師指定飯後（08:00、18:00）。
3. `ph01`「住院藥局」：下午做「每日調劑」（明天整天的劑量，一位病人一區，按「全部調劑」）；當天新開的醫囑列在最上面「補調劑」。胰島素筆這種無法逐劑換算的藥要填發幾支（床邊已有填 0）。「最近的調劑」每一張可印「簽收單」（依病房分張、依床號列出藥盒內容與核對藥師，下方送藥人、病房點收人簽名欄；病房點收後重印會印出系統記錄的點收人與時間）。調好的藥在「待核對」逐位病人核對：「核對送出」才扣住院藥局、送病房，發現錯誤「退回重調」（雙人核對設定開啟時，要換 `ph02` 核對）。病房送回的藥在「待退藥點收」點收入庫（短少寫原因）；還沒送回的另外列出供參考。核對送出後，`nurse01` 在護理站「本班待辦」的「藥車待點收」逐盒點收；有問題的按「不符」（短少、破損、不是這位病人的），藥局頁最上面出現「病房回報」，藥師處理時可逐行補發（從住院藥局扣）並寫說明。點收前照樣可以給藥，給藥列標「藥車未點收」；交班分頁會提醒還沒點收的藥車。
4. `nurse01`「護理站」：沒選病人時是全病房「本班待辦」（上方提醒本班病房常備還沒點班）、「常備點班」分頁逐項輸入實點數量（差異寫原因、自動調帳；有管制藥（Morphine 第二級、Tramadol 第四級，品項標「管制 N 級」）的要另一位護理師當場見證：按「完成點班」後由 `nurse02` 輸入自己的帳密；醫師開 Morphine「每次 0.5 AMP」時，給藥前也要 `nurse02` 見證殘餘 0.5 AMP 銷毀，`ph01` 在「藥品庫存 → 管制藥簿冊」看得到這一筆；示範：5A 的 Acetaminophen 只剩 25，低於基準量 40，`ph01` 在「住院藥局」頁「病房常備補充」補到基準量），點一列就到該病人；上方「待送回藥局」列出沒給的 UD 藥（暫停、拒絕、停止、出院病人的剩藥），勾選後「送回藥局」。醫師新開或停止的醫囑會標「新醫囑」，在「醫囑」分頁核對。依時間給藥（逾時標紅、太早不能給；藥局還沒調劑、或還在核對的標「待藥局調劑」「藥局核對中」，不能給；PRN、STAT 用病房常備，給藥時直接扣住院藥局）、記錄生命徵象（看趨勢圖）、Focus DAR 護理紀錄、交班（顯示最近三班，跨午夜不會消失）。
5. 片語在住院也能用：醫師的病程紀錄、出院病摘（`dr02`：`.stable`、`.cont`、`.opdfu`），護理師的護理紀錄、交班（`nurse01`：`.fall`、`.fever`、`.vs`）；欄位下方「管理片語」可新增修改。片語有個人的與共用的：醫師的**科室共用**（內科 `dr02`、`dr03` 都能用 `.dmedu`；`.htn` 兩人都有，`dr02` 展開的是自己的個人片語——同簡碼個人優先，管理畫面標「被你的個人片語蓋住」），護理師的**病房共用**跟著護理站目前選的病房（5A：`.turn`、`.iv`；換到 6B 就沒有）。共用片語同科／同病房的人都能改、能刪，記下最後修改的人。還有**全院共用**（醫師、護理師各一組，大家都能用，只有被指定「維護全院片語」的人能改：`dr01` 維護醫師那組 `.ama`、`.fu`，`nurse02` 維護護理那組 `.fall`、`.pain`）；優先順序個人 > 科室／病房 > 全院（`nurse01` 的 `.fall` 展開的是自己的個人片語，全院的那則標「被你的個人片語蓋住」）。
6. 會診與轉科：門診也能會診——`dr01` 看診時在病人上方「門診會診」按「會診」（書面會診，病人不必另外掛號），內科 `dr02` 門診頁左上「待回覆門診會診」回覆，`dr01` 首頁「會診已回覆」看過按已閱。住院：主治醫師在「住院醫囑」按「會診」開會診單（科別、目的、可勾急會診）；會診科醫師首頁待辦「待回覆會診」、病人清單上方打開，看會診單附的病人摘要後回覆評估與建議，可勾「建議轉本科」（示範：外科 `dr04` 有一張糖尿病病人左足傷口的會診；肺炎病人的耳鼻喉科會診已回覆）。會診醫師在會診對話框也能「開醫囑」（待回覆期間到回覆後 72 小時內；回覆後清單上標「已回覆・可開醫囑」），醫囑標「會診：外科 張皓宇」，只能停止自己開的；主治 `dr03` 的首頁待辦、病人清單（「會診醫囑 N」）、病人上方都提醒，按「已閱」才消失。主治看到建議轉科就按「依會診申請轉科」，科別、醫師、原因都帶好。申請轉科要寫**轉出摘要**（住院經過、目前問題必填）；新科醫師首頁待辦「轉入申請」，在病人清單上方打開 → 逐筆決定原醫囑延續或停止、可一併轉到本科病房的空床 → 接受（或寫原因婉拒）。示範：腦梗塞的病人已申請轉復健科，用 `dr09` 登入就能接受。
7. 主治醫師在「住院醫囑」的「出院病摘」分頁寫病摘（可存草稿），「簽署並准予出院」後，床位圖與護理站標「准出院」；病人狀況變了可取消（內容留成草稿）。
8. 出院帶藥：醫師在住院醫囑頁「出院病摘」下方開帶回家的藥（和門診開藥同一個編輯元件；一般最多 7 天，勾「慢性病」最多 30 天，簽署時檢查），`ph01`「住院藥局」最上面「出院帶藥」→「調劑完成」（從住院藥局扣帳）→ 印藥袋（住院藥局、出院帶藥）。調好後醫師要改，要藥局先「退回」（藥回原批號）才能取消准出院。種子：准出院的那位有 2 項出院帶藥待調劑。
9. `clerk01`「批價結帳 → 住院結帳」（首頁「住院待結帳」直接帶過去）：醫師簽准出院的病人排最前面，帳單依類別列出病房費／護理費／住院診察費（× 天數，入院當天算、出院當天不算）、藥費（實際扣帳的量）、已執行的檢驗處置、差額床費（雙人房、單人房依住的天數），部分負擔依住院天數分段（30 日內 10%、31–60 日 20%、61 日起 30%，有每次住院上限）→ 收款（現金可記欠款）→ 收據。其他住院病人可以先看試算；有出院帶藥的要等藥局調劑完（帳單才完整）才能結帳。結帳當天、出院前可「作廢重結」。
10. 「住院中心」辦理出院（醫師沒簽署、**還沒結帳**都不能辦；結帳後又有新費用——多住一天、又給藥、又做檢查——要櫃台作廢重結）→ 核對醫師的病摘、確認未執行項目 → 醫囑停止、未執行排程刪除、病床轉為清潔中。病摘之後在「病患資料」的「住院紀錄」查閱。示範：5A 病房有一位已准出院的病人。

**其他值得看的**

- 「系統管理 → 排班 → 單日調整」：停診（病人退掛＋通知名單）與代診（掛號轉給同科醫師）。通知名單櫃台在掛號頁就看得到，首頁也有待辦。掛號頁也有「停診／代診」（同一個元件）：權限「停診、代診」預設只有管理員，在「系統管理 → 權限」指定給櫃台組長（例：`clerk02`）後，他在掛號頁就看得到這個按鈕。
- 「藥品庫存」：每一筆庫存增減的異動帳、批號效期、盤點。**大型醫院**（系統管理 → 展示資料，重置時選「大型醫院」）有藥庫、門診藥局、住院藥局三個地點，頁面頂端選「目前地點」；多一個「撥補單」分頁：藥局「向藥庫請領」（需求清單列出低於該藥局安全庫存的藥與門診藥局的補貨申請）→ 藥庫撥發（依效期先到先出，可少撥，運送中）→ 藥局逐批簽收才入帳（短少寫原因）。反方向「退回藥庫」：藥局逐批勾選要退的批號（過期、近效期、存量偏多的排前面），寫原因「申請退回」（不扣帳、照常發藥）→ 藥庫逐批填同意收多少（少收寫原因），或整張「不收」→ 藥局按「送出」才扣帳、運送中（申請後已發掉的照現有的少送）→ 藥庫簽收時逐批選「入庫」「待報廢」（放進藥庫底下的「待報廢區」，過期的只能這樣）或「拒收退回」（寫原因，帳回到原藥局）；「待報廢區」分頁可以報廢或把沒過期的放回可用。首頁待辦「撥補待撥發」「撥補待簽收」；示範：藥庫有一張請領中的單（Cephalexin 藥庫缺貨只能撥 0、Acetaminophen 可撥）。藥品明細可改「這個地點」的安全庫存。「補貨待到貨」卡片列出已申請、還沒到貨的藥（有病人在等的排前面）。示範：Cephalexin 有一張昨天的申請，已列入待核准的採購單。
- 「藥品庫存 → 採購單」：`ph01`「開採購單」→ 選供應商（主檔裡往來中的；勾需求清單時自動帶上次買這種藥的那家，每一行提示「這家上次 X 元」）→ 從需求清單（待處理的補貨申請＋低於安全庫存的藥，附建議量、上次供應商與進價）勾選帶入 → 送出 → `admin` 首頁待辦「採購單待核准」→ 核准（或退回寫原因）→ `ph01` 對品項「到貨入庫」（批號效期照實物，可分批，超收擋下）→ 全部到齊自動「已到齊」；短交可結案。沒有採購單的入庫用「無單進貨」，要選原因。「供應商」分頁維護主檔（藥師、管理員都能改），點一家看「以前的進價」與其他供應商比價（較便宜的標橘色）；示範資料有一家已停用。「庫存地點」分頁新增、改名、停用地點，並指定門診發藥、住院調劑、採購入庫由哪裡負責（大型醫院示範：新增「急診藥局」→ 門診發藥改由它負責，醫師開藥看到的可用量就變成它的）。
- 「藥品庫存 → 盤點單」：`ph01` 建立（全部／劑型／指定藥品）→ 照架上實物填數量（**看不到帳上數量**；庫存頁、明細、調劑畫面這段期間也只顯示「盤點中」）→ 送出 → 換 `ph02`（或 `admin`）登入，看差異、寫原因後覆核過帳，或退回重盤。可列印清點表（不印帳上數量）、加「架上有、表上沒有」的批號。
- 「系統管理 → 收費設定」：調整部分負擔時右側即時試算；已開立的收據不受影響。部分負擔、掛號費（就醫身分）、醫令點數（主檔）都可以填「生效日」排定某天起調整，清單標「12/01 起…」；批價依看診日，生效日前看診、之後才批價的照舊價。
- 「系統管理 → 主檔 → 藥品」：編輯價格時填「價格生效日」（例：下個月 1 日），清單會提示「12/01 起 2.2」；批價依**看診日**的價格（示範：Metformin 已排定下個月調價、Amlodipine 3 天前調降，更早的收據是舊價）。
- 用 `admin` 進入任何臨床頁面：可以看，但操作會被擋下。

## 設計原則

這個專案是一頁一頁做出來的，每一頁都踩過坑。以下是整理出來的原則，每一條都附上程式中的對應位置。

### 1. 規則放在服務層；頁面的判斷只是為了體驗

頁面可以先判斷（勾不了不符資格的項目、按鈕反灰），但**服務層一定要再判斷一次**，因為頁面擋住的只是誠實的使用者。

- 掛號頁只列出符合資格的預防保健項目，`booking.register` 仍用同一個 `checkEligibility` 再檢查。曾經漏掉這一步，結果直接呼叫 API 就能讓男性掛子宮頸抹片，還會以 A3 案件申報。
- 給藥按鈕在「還沒到時間」時反灰，`nursing.executeMar` 一樣會擋。
- 「能不能掛號」由服務層算好 `SessionView.bookable`，頁面不自己組 `full || closed || suspended`。

### 2. 規則寫成純函式，所有人共用

同一條規則只寫一次，服務層、頁面即時提示、種子資料、測試都呼叫它，就不會各算各的。

| 部分退費 | `money.pendingRefundOf`：用**病人實際拿走的藥**（`rx-rules.keptMedications`：處方 − 已退）**＋實際做了的檢驗處置**（標「未執行」的不算：`charge.markProcedureNotDone`，櫃台標、寫原因，醫令照留只記執行狀態 `ProcedureOrder.notDone`；退費前可撤銷，退費後 `settledAt` 不能撤銷；收據作廢或整張退費重新批價時清掉；存病歷、同前次、組套一律拿掉這個欄位——只有批價能標）、同一個看診日價格、同一個身分與優免（結帳時的類別，不必重新核准）重算，和原收據（扣掉已經部分退過的）比——藥品部分負擔是分級的，退了藥可能剛好降一級，差額一起退；也可能部分負擔不變而退 0 元，只更正申報點數。`charge.refundReturnedDrugs`：收據不作廢、原本那天的帳不動，差額**先抵這張收據還沒收回的欠款**，剩下的依原付款方式退（扣抵的預收視同已付），開退款單算在今天（`Charge.partialRefunds`；不退錢就不開單）。日結：退款列「部分退費」、申報點數扣掉退掉的藥。之後剩下的也退完、整張退費時，扣掉已部分退過的；部分退費過的收據不能作廢。可能是好幾天前看的診，所以批價頁另列「待退費」（`listPendingRefunds`）、首頁待辦也有 |
| 掛號預收 | 掛號時選填（只限掛號批價人員）：開預收收據、算在收的那天（`money.takePrepay`）。**預收款屬於這次就醫、不屬於某張收據**（`Visit.prepay`）：批價時扣抵（`Charge.prepaidApplied`），多收的當場開退款單退還、不夠的補收；收據作廢或退費後預收款還在，重新批價再扣抵；改期跟著走；退掛當場退還；停診（病人不在現場）列在停診通知名單「待退預收」，櫃台聯絡上再退（`refundSuspendedPrepay`），日期過了也不會從名單消失。日結：預收算在收的那天，批價扣抵的部分從那天的應收減掉——同一筆錢不會算兩次；實收＝應收 − 新欠 − 預收扣抵 ＋ 收回 ＋ 預收 − 退款 |
| 優免（批價減免） | **送簽**（`charge.requestDiscountApproval`／`decideDiscountRequest`，`db.discountRequests`）：櫃台送簽、主管在首頁核准或退回（退回要原因），核准綁「這次掛號＋類別＋送簽的櫃台」、當天有效、結帳時用掉（`used`），存在資料庫（要等主管，不能只放記憶體）；同一次掛號重送會撤回舊的；不能核准自己送簽的；病人已批價就不必處理。和當場核准並存。`billing.applyDiscount`：只減掛號費與自費項目，加負數的優免列；**部分負擔一律不減**（健保法禁止醫院自行減免），申報點數不變。**主管核准**（`charge.approveDiscount`）：類別設「需主管核准」時，由帳號設定「可核准優免」的另一個人當場輸入帳密；核准是一次性的，綁「這次掛號＋這個類別＋這位櫃台」、10 分鐘內有效，結帳時用掉（存在記憶體不進資料庫，重新整理要重新核准）。帳密錯、沒權限、核准自己都**回傳**失敗而不丟錯——mutate 丟錯會連稽核一起回滾，失敗的嘗試就查不到了（共用 `witness-core`，見「第二人當場確認」） |
| 處方天數一次改完 | `dose-rules.applyDaysToAll`：可換算的總量重算；總量手動填的、無法換算的（Insulin、眼藥水）保留並標「天數已改，請確認總量」；天數不合法一筆都不改 |
| 藥品搜尋（開藥、住院醫囑、藥品庫存、主檔） | `drug-rules.matchesDrug`：代碼、英文藥名、學名、健保碼、中文名、別名、作用都比對——打「普拿疼」「降血壓」都找得到 |
| 服用時機（藥袋、藥局處方表） | `drug-rules.timingText`：只有口服才印；頻率是睡前、需要時、立即的不印（`timingApplies`，開藥畫面的時機選單也看它） |
| 單一處方改服用時機 | `drug-rules.effectiveTiming`（醫師指定優先，否則照主檔）、`normalizeRxTiming`：門診處方只存「和主檔不同、而且適用」的指定（完成看診、存組套都經 `views.cleanRxTimings`）——組套、同前次複製處方時，主檔之後改了也跟著改。住院醫囑開立時把**有效時機存在醫囑上**，主檔之後改了不影響已排的劑量（否則 07:00 和新算的 08:00 會同時存在，病人多一劑）；要改就停掉重開。藥局處方表、住院醫囑、護理站標「醫師指定」 |
| 住院給藥時間 | `drug-rules.marTimes`：一天幾次的頻率（QD／BID／TID／QID）對齊病房用餐（早 07:30、午 12:00、晚 17:30）——飯前提前 30 分、飯後延後 30 分、空腹提前 1 小時、隨餐就是用餐時間；BID 早晚、QID 第 4 次在睡前 21:00。飯前飯後皆可、間隔型（Q6H／Q8H／Q12H）、睡前、非口服照頻率的固定時間。`ipd.ensureMar` 與種子都只呼叫它（流程測試掃描）；開醫囑對話框預覽每天幾點給 |
| 供應商主檔 | `purchase-rules.taxIdProblem`（統一編號 8 碼＋檢查碼：加權 1,2,1,2,1,2,4,1、乘積位數和能被 5 整除，第 7 碼是 7 的特例），主檔表單即時提示與服務層同一條；`normalizeSupplierName` 比對同名（含停用的——停用的請直接啟用，兩筆同一家進價紀錄就分散了）。採購單只能選啟用中的，存供應商 id 與**開單時的名稱**（單據是文件，供應商改名舊單不變）；還有進行中採購單的不能停用。「以前的進價」（`supplierPrices`）：每種藥這家最近一次＋其他供應商最近一次，只算核准訂購過的單（待核准可能被退回） |
| 建議補貨量 | `stock-rules.suggestRestockQty`：（等候中的處方 − 現有 − 已申請未到貨）＋安全庫存＋14 天用量，進位到 10；對話框顯示算式，種子資料也用它 |
| 預防保健欄位格式（血壓、血糖…）與 BMI | `prevent-rules.FIELD_FORMATS`、`calcBmi`：BMI 由身高體重算，不讓人填 |
| 藥品同名判斷 | `services/drug-rules.ts`（`sameNameDrugs`、`needsSameNameCheck`） |
| 過敏比對 | `services/allergy.ts` |
| 劑量合理性、處方天數 | `services/dose-rules.ts` |

**防打錯的規則看「倍數」，不看絕對值。** 各藥的劑量刻度差很多（1 顆錠劑對 10 U Insulin），所以劑量以「該藥常用劑量的幾倍」判斷：超過 3 倍（高警訊藥品 2 倍）要醫師確認，超過 20 倍幾乎一定是多打了 0，直接擋下。處方天數限 1–30 天，收款找零上萬元視為輸入錯誤。這些不是臨床上限，而是攔住「多打一個 0」的防線，門診、住院、頁面即時提示都呼叫同一個函式。

**規則是程式，參數是資料。** 部分負擔的金額可以在系統管理調整，計算方式不行；預防保健項目可以調整間隔與欄位，但不能在畫面上新增項目，因為新項目代表新的資格邏輯。

### 3. 每一種檢查只有一個入口

規則散落在各處，就會出現「門診有檢查、住院沒檢查」。

| 檢查 | 唯一入口 |
|---|---|
| 登入 | `query()` 預設必須登入，公開的要明確寫 `{ public: true }` |
| 角色 | `requireUser(...roles)`，管理員也不會自動通過 |
| 誰能看到什麼資料 | 在服務層決定、不是在畫面上藏：首頁「今日收入」只回傳給掛號批價與管理員，其他角色的 `getDashboard` 根本不含這筆資料 |
| 主檔停用 | `usable.drug / procedure / icd`：開立新單一律經過它，顯示舊紀錄則用 `find` |
| 庫存異動 | `inventory.postStock`：唯一能改庫存的函式 |
| 建立掛號 | `booking.createVisit`：掛號與改期共用，改期不能繞過診次、重複、預防保健資格任何一條 |
| 「同一份名單」的範圍 | 停診待通知 `schedule.suspendNoticeVisits`（名單與首頁待辦）、預防保健已登錄 `prevent.visitItems`（工作清單與看診頁）、待領藥 `pharmacy.awaitingPickup`（藥局清單與首頁）——兩個地方顯示的數字，用同一個函式算（流程測試比對兩邊相等） |
| 登入後導向 | `utils/redirect.ts` 的 `safeRedirect`：路由守衛與登入頁共用；只接受站內路徑（拒絕 `//`、反斜線、外部網址），權限仍交給守衛 |

### 4. 寫入是交易；回傳的是複本；參數經過「網路」

`services/http.ts` 的 `mutate()` 先拍快照，失敗就整個回滾，不會留下改到一半的資料；成功時先複製回傳值，再存檔。`overNetwork()` 讓所有參數經過 JSON 序列化，模擬真實後端只收得到純資料，頁面的 Vue Proxy 不會被存進資料庫。

- **存檔失敗也是交易失敗**：`mock/db.ts` 的 `commit()` 寫不進 localStorage（通常是空間已滿）時丟出錯誤，由 `mutate()` 回滾並告訴使用者。以前是默默吞掉，畫面顯示收款成功、給了收據號，重新整理後資料卻不見了。
- **讀取時順便產生的資料例外**：診次、給藥排程這類「查詢時才補產生」的資料用 `commitIfPossible()`，存不進去也不影響這次查詢，下次會再產生；使用者的操作一律走 `mutate → commit`。
- **頁面層要複製資料用 `clonePlain`**（`utils/clone.ts`）：頁面的資料常是 Vue 的 Proxy，`structuredClone` 複製不了會直接丟錯（病患資料頁按「修改」曾因此打不開）。頁面資料都是純資料，用 JSON 來回一次，和 `overNetwork` 同一個道理。

### 5. 狀態機

狀態的轉移都在服務層檢查，不能跳步：

- 掛號：已掛號 → 看診中 → 已看診 → 已批價 → 已領藥（或已退掛）
- 調劑：待調劑 → 已核對 → 已發藥
- 住院：預約 → 住院中 → 出院（或取消）
- 病床：空床 → 使用中 → 清潔中 → 空床（或保留）
- 給藥：待給 → 已給／暫停／拒絕

### 6. 紀錄只能增補，不能改寫

- 庫存是**帳本**（`StockTxn`）：每一筆增減都有時間、人、單據、原因與結存；`drug.stock` 只是快取，測試會驗證它永遠等於帳本加總。主檔維護不能順手改庫存。
- 護理紀錄的「反應（R）」、預防保健的「待報告」只能補一次，補完就定案。
- 收據保存開立當時的明細，日後調整收費設定，舊收據不會變。
- **藥價看「看診日」，不是「批價日」**：調價日之前看診、之後才來批價的，收看診那天的價格（健保申報也依就醫日）；否則同一天看診的兩個人，會因為誰先結帳而價格不同。主檔的 `nhiPrice` 是最早的原價，之後的價格存在 `priceChanges`，**任何地方要價格都用 `drugPriceOn`**（流程測試掃描批價原始碼，不得直接讀主檔價格）。生效日不能早於今天：回溯調價會悄悄改掉已看診、還沒批價的人的金額。
- 稽核紀錄沒有任何修改或刪除的 API。
- **登錄錯了用「作廢」，不是改或刪**：預防保健紀錄作廢（`voidPreventRecord`）只加上原因、時間、作廢人，原內容不動；作廢後不佔資格、不計統計，可以重新登錄正確的一筆。
- **換人負責要留下經過**：變更主治醫師（`changeAttending`）把「誰、何時、從誰換成誰、為什麼」附加到 `attendingHistory`。
- **狀態可以改回去，歷史留在稽核**：停診通知的「已通知」可以撤銷（`unmarkNotified`），稽核紀錄記下原本是誰、何時記錄的。
- **改期不是改掛號，是退舊掛新**（`rescheduleVisit`）：原掛號留下「改期至 日期 診別 科別 醫師 第 N 號」，新診次掛不上就整筆回滾。
- **身分更正只限收費前**（`correctIdentity`）：已開收據的要先作廢，因為收據存的是當時算好的金額；稽核記下前後身分與原因。
- **核對醫囑留下是誰、何時**（`ackOrders`）：只核對畫面上看得到的那幾筆——醫師剛好又開的新醫囑，護理師還沒看到就不能被一起簽掉。可以逐筆核對，也可以「全部核對」（交班常用）。
- **有疑問就退回醫師，疑問期間暫停執行**（`queryOrder`、`replyOrderQuery`）：護理師寫疑問後，那筆醫囑不能核對（整批核對自動跳過）、給藥與臨時醫囑的執行暫停（`holdForQuery`，排程給藥、PRN、臨時醫囑共用一條）；緊急時可寫原因強制執行，記在給藥紀錄與稽核。醫師在病人清單「疑問 N」、首頁待辦看到，回覆「確認無誤」（寫說明）後護理師要看到回覆再核對一次；要改劑量、頻率、途徑、時機就按「修改醫囑」（`reviseOrder`）：畫面一步，資料上仍是「停止舊的＋開新的」兩筆、互相標記（已給的藥掛在舊醫囑上，直接改舊醫囑的劑量會讓以前的給藥紀錄看起來像照新劑量給的）；檢查與開新醫囑共用 `createOrder`；疑問記為「已修改」並自動寫出改了什麼。**從下一劑開始**：新醫囑的起始時間取「現在」與「舊醫囑最後一劑已處理的時間」較晚者——12:00 那劑提早在 11:40 給了、11:55 改劑量，不會在 12:00 再排一劑。換藥則停止那筆（疑問記為「已停止此醫囑」）再另開。疑問與回覆可以多輪，全部留在醫囑上。
- **補登不是改寫時間，是兩個時間都留**：先給藥、後登打時，`executedAt` 記實際給藥時間、`recordedAt` 記登打時間，畫面顯示「13:05（13:51 補登）」。補登時間不能晚於現在、不能早於可給藥時間（和「太早不能給」同一條 `marUrgency`）、最多往前 2 小時（`nursing-rules.checkGivenAt`）。
- **保留床一定是保留給某個人**（`Bed.reservedFor`）：那位病人報到時可以直接選這床；預約取消或報到在別床時，系統自動解除保留並寫稽核——不會有沒人知道為誰保留、永遠佔著的床。
- **出院不能把沒給的藥一起刪掉**：出院前先列出逾時未給的藥、未執行的臨時醫囑（`dischargeCheck`），要勾選確認才能出院（服務層也擋）；逾時未給的藥改為「暫停：出院時未給藥」留在紀錄上，只有還沒到時間的排程才取消——以前一律刪除，紀錄上就像從來沒排過。
- **醫囑停止、完成都要有時間**：`stopAt` 是「新／已停／已完成」判斷的依據，流程測試檢查每一筆非執行中的醫囑都有它（曾經漏在臨時給藥與種子資料）。

### 7. 被引用過的只能停用，不能刪除；動手前先看會影響誰

- 科別、醫師、藥品、醫令、診斷碼都只能停用。停用前會列出還在用它的資料（未看診掛號、住院病人、排班、執行中醫囑）。
- **例外：個人設定可以刪除**。組套（`orderSets`，個人或科室共用）、片語（`phrases`）不是醫療紀錄、也沒有被別的資料引用，刪除只寫稽核。組套裡的藥日後停用了，**套用時才檢查**（`expandOrderSet` 濾掉並列出），存的時候能開不代表半年後還能開。
- **科室組套大家都能改，就要看得出是誰改的**：同科在職醫師都能套用、覆蓋、刪除（`orderset.canUse`：個人的看 doctorId、科室的看「目前」所屬科別，轉科後就看不到原科室的），每次存檔記下 `updatedBy`，清單標「最後修改 黃柏翰 11/10」，覆蓋前的確認也說出上一位修改的人；稽核寫明「內科科室組套」。個人與科室可以同名（選單用分組分開）。
- **片語展開不能吃掉醫師打的字**：規則在 `phrase-rules.expandPhrase`——游標前緊接著「.簡碼」、而且前面是開頭／空白／中文標點才展開（「3.5mg」不會），找不到的簡碼原樣保留、照常輸入空白；**中文輸入法選字時（`isComposing`）按空白是在選字，不攔**；Shift+Tab 不攔。只有真的展開時才 `preventDefault`，所以一般的 Tab 照常跳到下一欄。按鍵處理只有一份（`composables/usePhrases`）：門診 SOAP、住院病程與出院病摘、護理紀錄、交班都用它（流程測試掃描頁面不得自己呼叫 `expandPhrase`）。
- **共用的東西不能蓋掉個人的習慣**：片語同簡碼可以並存，個人 > 科室／病房共用 > 全院共用——順序由服務層決定（`phrase.listPhrases` 依 `rankOf` 排），`expandPhrase` 取第一個符合的，頁面不另寫判斷；被蓋住的共用片語在管理畫面標出來，不然有人改了共用的 `.htn`、自己卻怎麼打都是舊句子，會以為壞了。護理師的病房共用片語看「目前所在的病房」（`usePhrases(() => 病房)`），不綁帳號：支援別的病房時用的是那個病房的說法。
- **把舊內容帶進新處方，只有一個入口判斷停用**：組套、「同前次」、「只帶處方」都經過服務層的 `pickUsable`（`src/services/views.ts`），停用的藥、處置、診斷碼濾掉並告訴醫師；頁面的合併規則也只有 `mergeIntoDraft` 一份（重複的略過、診斷與 S／A／P 只填空白的）。以前從歷史複製處方沒有過濾，停用藥要到完成看診才被擋。
- **「同前次」不帶 S 主訴、O 客觀、生命徵象**：那是本次的事實，照抄上次的（例如「無發燒」）會讓病歷與實情不符；只帶診斷、藥品、處置、A 評估、P 計畫（`expandEncounter`）。前次是慢箋調劑（不是看診、沒有評估計畫）時，改帶原處方那次看診。
- 停診時已掛號的病人不能就這樣消失：會退掛，並進入「停診通知」名單，直到逐一電話通知完成。
- 修改每週排班只影響還沒有人掛號的未來診次。
- 管理員不能停用自己、不能拿掉自己的管理員角色；系統至少保留一個啟用的管理員（縱深防禦）。

### 8. 畫面上的資料，要和它依據的來源保持同一個版本

- **BFF**：需要多份資料的畫面，由服務層一次組好回傳，例如 `getChargeDetail`、`getMarBoard`、`getPreventProfile`、`getDrugLedger`、`getSessionImpact`，避免各自查詢、彼此不同步。
- **id 比對**：切換病人時，查詢結果帶著「這是誰的資料」，id 對不上就不顯示，舊病人的資料不會閃過新病人的畫面。
- **只存 id，不存快照**：從清單點進明細時，只記 id，資料每次從最新清單取得。
- **載入中不等於沒有資料**：`UQueryState` 統一處理載入、空、有資料三種狀態；`USearchSelect` 在防抖等待時也算「搜尋中」。

### 9. 時間是資料的一部分

- **全系統只有一個時鐘**：`composables/useClock.ts` 一個計時器、每 30 秒更新，所有頁面讀同一個「現在」與「今天」（`useNow` 是它的舊名稱）。「逾時、待給、太早」依它即時計算（＋`marUrgency`）。
- **「今天」會走動**：頁面打開時記下 `today()` 就不會再變，開著跨過午夜，護理站還停在昨天，而大夜班正是跨夜的人。`followToday(date)` 讓日期欄位跟著新的一天走；使用者自己選了別的日期（例如查昨天的日結）就不去動它。
- 「每 N 年」定義為同月同日（`addYears`，2/29 會進位到 3/1），不用 N × 365 天。
- 帳本依寫入順序排序，不依時間排序：時間只到分鐘，同一分鐘的兩筆分不出先後。同樣的道理，「最新一筆生命徵象」同一分鐘有兩筆時取後寫入的（曾經取到舊值）。
- **交班屬於「班」，不屬於日曆日**：11/10 的小夜常在 11/11 00:10 才寫完交班，它仍是「11/10 小夜」（`shiftInstanceOf`）。交班清單顯示最近三班，不是「今天」——以前依今天查，大夜 00:15 就看不到小夜 23:45 寫的交班。
- **沒做完的工作要跨日帶著走**：藥局「待調劑」包含前幾天開立還沒領的單（標日期，領藥號每天重編）；「已發藥」依發藥時間算，不是開立日。
- **「本班待辦」的範圍跟著班走**（`shiftRange`）：逾時、可給的給藥一律列出（含 15:30 時已可提早給的 16:10），還沒到時間的只列到本班結束——和病人清單的徽章是同一個範圍。

### 10. 種子資料也要守規則

展示資料不能違反臨床常識，否則展示時就在示範錯誤。

- 開藥避開病人的過敏藥物（`checkAllergies`），預防保健紀錄都符合資格（`checkEligibility`）。
- 成人病房只住成人；小兒科只看 13 歲以下、婦產科只看女性（`deptFits`）。
- 庫存帳用與服務層相同的 FEFO 規則依時間順序「重播」產生；不足時直接報錯，不默默略過。
- 時間軸要合理：掛號 ≤ 叫號 ≤ 完成看診 ≤ 批價 ≤ 發藥；看診號、收據號、領藥號、就醫序號都依時間先後（資料分段產生，最後統一依時間重編）。以前過去的就醫會「還沒看完就先付錢」，收據號 R0002 比 R0003 晚。
- 不能有晚於「現在」的時間（早上 8 點不該已經有 10:30 的發藥紀錄；清晨開啟時，當天 08:30 的查房紀錄也不能先出現）。
- 展示用的住院醫囑都視為「之前開的、已核對過」——否則一打開護理站，每位病人都掛著「新醫囑」，真正新開的反而被淹沒。
- 流程測試會逐一驗證以上幾點；測試裡的檢查是**另外獨立寫的**，不重用種子資料裡的函式。

### 11. 多分頁：資料共用，登入身分各自獨立

| 存什麼 | 存在哪 | 範圍 |
|---|---|---|
| 資料（病人、醫囑…） | `localStorage`（`mock/db.ts`） | 所有分頁共用 |
| 誰登入了 | `sessionStorage`（`services/http.ts` 的 `setSessionUser`） | 只屬於這一個分頁 |
| 畫面是否鎖定 | `sessionStorage`（`setSessionLock`） | 只屬於這一個分頁；重新整理仍鎖定 |

- **資料要同步**：每個分頁在記憶體各握一份資料庫，寫入時整份寫回。若不同步，分頁 B 的下一次寫入會把分頁 A 剛建的病人蓋掉。所以監聽 `storage` 事件（只有**其他**分頁寫入才會觸發），收到就重新載入並通知頁面重新查詢。
- **登入身分刻意不共用**：展示時常一個分頁登入醫師、另一個登入藥師，並排看醫囑送到藥局。代價是在 A 分頁登入，B 分頁按 F5 仍是未登入（「複製分頁」會帶走一份當下的登入）。真實系統多半相反：憑證放在 cookie，所有分頁共用。

- **閒置鎖定，不是登出**（`services/idle-rules.ts`、`composables/useIdleLock.ts`、`components/LockScreen.vue`）：預設 15 分鐘沒有點擊、按鍵、捲動就鎖定畫面（管理員可在「系統管理 → 安全設定」改為 1–60 分鐘），鎖定前倒數提醒。直接登出會讓寫到一半的病歷消失，所以是鎖定：整個畫面蓋住，同一人輸入密碼回到原畫面、沒存的內容還在；換人使用按「切換使用者」才真正登出；密碼連錯 5 次強制登出。鎖定中服務層的 `requireUser` 一律拒絕（LOCKED，頁面不提示），直接呼叫 API 或按 F5 都繞不過；背後的元素設為 `inert`，Tab 也跳不到。計時用「最後操作時間＋現在時間」算，不靠倒數——背景分頁的計時器會被瀏覽器放慢、電腦睡眠會暫停，醒來一算就知道該鎖。各分頁登入各自獨立，所以也各自鎖定。

- **密碼**（`services/password-rules.ts`）：自己變更、管理員新增帳號與重設都用同一套規則（至少 8 碼、英文字母加數字、不可包含帳號、不可與目前相同；既有的 1234 照樣能登入，規則只管「設定新密碼」）。變更要輸入目前密碼（座位上沒登出的電腦，別人不能順手改掉密碼占用帳號）。管理員設定的密碼（新帳號、重設）本人登入後必須先改，改之前服務層 `requireUser` 一律拒絕（PASSWORD_CHANGE），不是只有畫面擋。每個分頁記下登入時間（毫秒），密碼變更後比變更時間早登入的分頁全部失效——密碼外洩時改密碼，就能把別人踢出去；改密碼的那個分頁則繼續登入。**期限與歷史**（`passwordAge`、`reusedPassword`、`checkPasswordPolicy`）：預設 90 天到期、不可重複最近 3 次（含目前這組），管理員在「安全設定」調整（期限 0＝不限）。期限從本人設定那天（`User.passwordSetOn`）算，到期前 14 天右上角提醒、帳號清單標出；過期後和管理員設定的密碼一樣只能改密碼或登出（`requireUser` 擋，不是只有畫面）；**過期超過寬限天數就鎖帳號**（`passwordLocked`，預設 30 天、0＝不鎖）：登入時（密碼對了才說，不能拿來試帳號）與已登入分頁的下一個動作都擋，要管理員「重設密碼」解鎖（重設後本人先改密碼）；帳號清單標「已鎖定」。例外：沒有其他「啟用、沒被鎖」的管理員時，管理員自己不鎖（`passwordLockOf`），不然全院沒人能解鎖。期限用另一個日期欄位，不用踢分頁的 `passwordChangedAt`——種子若設那個，每次「重置展示資料」都會把管理員自己踢出去。以前的密碼只在服務層比對、不送到畫面；管理員重設前的舊密碼與給的暫時密碼都記進歷史（本人不能改回外洩的那組）。示範：`nurse02` 的密碼 80 天前設定（右上角「密碼 10 天後到期」），把期限改成 60 天就會過期；`clerk03` 130 天前設定（過期 40 天），已鎖定。

- **權限只能「在規則內調整」**（`services/permission-rules.ts` 的權限目錄、`http.requirePermission`、`services/permission.ts`）：每個受控操作在目錄裡一筆——法規與醫療責任允許的角色（`candidates`，程式碼）、預設、是否固定、可否指定給個人。系統管理「權限」只能在範圍內勾選、至少留一個角色（可指定個人的權限，已指定了人就可以全部取消角色，例：藥庫作業只給藥庫藥師；這時最後一位不能收回、不能停用帳號）；固定的（開醫囑、給藥、發藥、收費、帳號與權限）不能改——把開醫囑勾給櫃台會出現沒有醫師的醫囑。主管型權限可以指定給個人（採購核准給藥劑部主管、優免核准給櫃台組長，取代以前的「可核准優免」帳號欄位）。調整要寫原因、寫稽核；會讓人失去權限的，先列出受影響的帳號再確認。**服務層、設定畫面、說明表格讀同一份目錄**：以前「主要操作權限」是手寫摘要，第一版就和程式不符；流程測試掃描原始碼，確認目錄每一項都有服務層在檢查、服務層檢查的都在目錄裡。登入資料帶 `can`（這個分頁能做哪些），頁面據此不顯示按鈕（`composables/useCan`），把關仍在服務層。
- **一個帳號多個角色，同一時間用一個**（`services/role-rules.ts`、`http.ts` 的 `sessionRole`）：帳號存 `roles`，每個分頁記一個「作業角色」（登入時選、右上角切換，不必重新登入）。服務層的 `requireUser` 回傳帳號加上作業角色，所以每條以角色寫的規則意思都不變——不採「所有角色的權限加總」，否則「護理師兼櫃台新增過敏，算誰登錄」「醫師兼管理員，『管理員不能臨床』還算不算」都變得模糊。帳號其實有那個角色、只是現在用別的角色時，錯誤訊息直接說「請切換為某角色」。稽核每筆都記下當時的角色。醫師＋藥師不可兼任（醫藥分業）。管理員拿掉某人正在用的角色時，那個分頁改用他剩下的角色並提示，不登出。

- **診間是主檔，不是自由輸入**（`schedule.saveRoom`）：每週門診表的診間只能從啟用中的診間選，已被同時段其他門診占用的列出來但不能選、寫明誰在用；服務層也檢查（以前打「2O1」就多出一間不存在的診間）。診間號建立後不能改；還有門診表在用的不能停用。位置印在掛號單上。

### 12. 替使用者擋下意外

- **對話框防誤關**（`components/ui/UDialog.vue`）：輸入或選擇過內容後，點背景、按 Esc 都不會關，只能按「取消」或 ×，醫囑、出院摘要寫到一半不會消失；沒輸入過的確認框照舊可以點背景關閉。
- **游標位置**：對話框打開時游標移到第一個輸入欄位，關閉時回到打開前的按鈕，鍵盤使用者不必按一堆 Tab。
- **按 Enter 送出，但不是每個對話框**：`UDialog` 綁了 `@submit` 才以 `<form>` 呈現，單行欄位按 Enter 送出、多行文字框按 Enter 換行。只給「送出後還能修改」的資料維護表單（進貨、盤點、帳號、主檔、排班、預防保健登錄…）；**開立醫囑、辦理出院、停診刻意不綁**——手還在輸入劑量時誤按 Enter 就開出一筆醫囑，這類動作必須明確按下按鈕。
- **能撤銷就不必先問**：停診通知的「已通知」要連續按幾十次，每次都確認只會讓人不看就按「確定」；改成按錯可以撤銷（撤銷才確認，因為少用）。
- **提醒，但由服務層判斷**：新增同名藥品不是錯誤（不同廠牌），但要提醒。流程是先送出 → 服務層查出同名回 `CONFLICT` → 頁面確認 → 帶 `allowSameName` 重送；其他欄位的錯誤會先回報，不會先問了同名才發現欄位沒填。使用者按「取消」時丟出 `Cancelled`（`composables/useService.ts`），`useAction` 安靜結束，不顯示錯誤。
- **盲盤要在服務層遮，不是畫面藏**：清點中，帳上數量、差異根本不出服務層（盤點單不給 systemQty；庫存清單、明細、補貨建議量、調劑單的庫存欄都回 0 並標出盤點單號）。只在畫面上藏，打開開發者工具就看得到；而且「可用天數」「偏低」標籤、補貨建議量都是用數量算的，一樣會洩漏，要一起遮。缺藥判斷（能不能核對）仍用真的數量——拿遮掉的 0 判斷會把有貨的藥擋下。
- **盤點期間照常發藥，差異以「清點那一刻」為準**：每填一批，服務層記下那一刻的帳上數量；過帳時差異套用到「現在」的帳。拿建立盤點單時的帳來比，盤點期間發出去的藥會全部變成盤虧。清點後那一批又被發光、帳上不夠扣盤虧時，整張不過帳，請退回重盤。
- **連續輸入的存檔要排隊**：盤點表一列填完按 Enter／Tab 馬上下一列。以前共用一個 `useAction`（進行中就忽略新的呼叫），上一列還在存時下一列的存檔被吞掉——數字留在格子裡，其實沒存。改成排隊依序送、每列顯示「儲存中」，送出前先等所有存檔完成。
- **不合法的輸入不拿來計算**：盤點輸入 -3 時，以前同時出現錯誤和「差異 -23（盤虧）」。輸入不合法就只顯示錯誤，不顯示差異、確認鈕停用，Enter 也送不出去。
- **發藥前確認領藥的是誰**：按「發藥」要輸入病人說出的出生月日（4 碼，服務層比對），或勾「他人代領」登記代領人與關係；兩種都記在調劑單與稽核。生日在病人資料列上本來就看得到——這一步的用意是逼藥師真的開口問。
- **一鍵做完，但把關不省略**：門診「完成並叫下一位」（Ctrl+Enter）把三個動作合成一個，過敏、劑量確認照樣跳出；任何一步沒成功（按了取消、缺診斷、服務層擋下）就停在原病人，不會往下叫。快速鍵只在看診中可編輯時有效。
- **搜尋時 Enter 直接選取**：藥局、批價清單只剩一筆符合時，Enter 就選中並切到它所在的分頁。藥局的 1–3 位數字只比對領藥號——否則打「4」連病歷號含 4 的人都找出來，就選不到唯一一筆。
- **窄螢幕捲到明細**（`composables/useRevealOnNarrow.ts`）：手機上左右兩欄變成上下堆疊，點清單後明細出現在畫面外，使用者以為沒反應。選取改變時把 `data-detail` 區塊捲進畫面；寬螢幕兩欄並排時不動作。

### 13. 資料版本號

`mock/db.ts` 的 `SCHEMA_VERSION` 一變，瀏覽器裡的舊資料會自動重建。

- **要調**：結構不相容地改變（新增必要的資料表），或種子資料的內容改變。
- **不用調**：只新增選用欄位，舊資料缺少它也能正常運作。
- **一定最後才調**：開發伺服器在版本號改變的當下就會重建資料，先調版本號再改種子，就會得到「新版本號＋舊內容」的資料。

### 14. 錯誤要指到欄位，而且一次說完

「改一個、送出、再冒出下一個」是表單最惱人的體驗；只在頂端說「請填寫報告內容」而不標出是哪一格，也一樣。

- **`failFields(errors)`**（`services/http.ts`）：一次丟出多個欄位錯誤，`ServiceError.fields` 帶著全部，`useAction` 把它放進 `fieldErrors`，每個欄位底下各自顯示。只有一個欄位時用 `failField`。
- **`fieldErrors()` 收集器**：必填、格式、範圍先全部收集，`done()` 一次回報；**欄位都對了才檢查規則**（重複、同名、停用前影響），因為規則常常要依賴欄位已經正確。同一欄位只留第一個錯誤（效期空白時只說「請輸入效期」，不再接著說「效期已過」）。
- **純規則函式回傳錯誤物件，不直接丟出**：`checkPreventResult` 回傳 `{ 欄位: 訊息 }`，服務層交給 `failFields`，頁面也能拿來即時提示。
- **要不要一起報，看規則本身**：補登預防保健報告時，每個結果都要填報告，所以「沒選結果」和「沒填報告」一起標出；新登錄時可選「待報告」（不用填欄位），沒選結果就只標結果——先標欄位會誤導。
- **訊息先說怎麼辦**：匯入不完整的檔案時說「這不是完整的匯出檔，請使用本系統「匯出資料」產生的檔案」，缺少的資料表名稱放第二行、最多列 5 個給工程人員查；以前一口氣列出約 40 個英文表名。

### 15. 列印

收據、藥袋、日結報表、掛號單都用瀏覽器列印，規則在 `style.css` 的 `@media print`：

- **只印 `.print-area`**：無關的元素 `display: none`（不佔空間）；列印區塊的上層（版面、捲動區、對話框）用 `:has(.print-area)` 改回一般排版，拿掉 `fixed`、`overflow`、限高。以前用 `visibility: hidden` 加絕對定位，藥袋超過一頁就被截掉、收據外框被拉到頁尾。
- **內容多就自然分頁**：日結報表 60 筆印成 3 頁；藥袋每張固定高度（`print:h-[134mm]`，兩欄兩列，A4 一頁 4 張），不會一張跨兩頁（實測 3／8／9／15 張分別印成 1／2／3／4 頁）。
- **匯出和列印用同一份報表**：服務層的純函式先把報表整理成「報表表格」（`dailyReportTable`、`controlledLedgerTable`，`services/report-csv.ts`），CSV 與 Excel 都從它產生，頁面只負責下載——畫面、紙本、CSV、Excel 的數字不會各算各的。
- **Excel 自己產生、不加套件**（`services/xlsx.ts`）：xlsx 是一包 XML 用 zip 包起來，只寫簡單表格的話 zip 不必壓縮（stored），連 CRC32 不到兩百行；常見的套件不是在 npm 停在有安全通報的舊版，就是約 1MB。金額、數量是數字（可加總）；病歷號、收據號、日期一律是文字（開頭的 0 不會掉、不會被轉成日期）；文字存成 inline string，不會被當公式執行；XML 不允許的控制字元拿掉；表頭粗體並凍結、欄寬依內容（中文算兩格）；日期固定，同樣內容產生同樣的檔。測試把檔案拆開核對 zip 結構、CRC、型別與轉義；開發時另用 Excel 開過、用它的 SUMIFS 核對金額。
- CSV 的細節：開頭加 BOM（Excel 才不會把 UTF-8 中文開成亂碼）；以 `= + - @` 開頭的文字前面加 `'`，病人姓名不能變成 Excel 公式（CSV 注入）；合計列的名稱不和明細的「類別」同名，篩選時不會混進來。
- **紙本要能追溯**：日結報表的表頭印出報表日期（區間報表印期間）、**列印時間與列印人**——同一天印兩次數字不同時，查得出哪張是何時誰印的。列印時間在按下「列印」那一刻取值。
- **藥袋**（`pharmacy/components/DrugBagLabels.vue`）：藥師法規定的欄位都印——藥局名稱地址電話（`utils/hospital.ts`，收據、掛號單、日結共用）、病人姓名性別年齡、藥名規格、用法劑量、天數總量、**作用、注意事項**（藥品主檔必填，管理員新增藥品沒填會被擋）、**服用時機**（藥品主檔欄位：飯前、飯後、隨餐、空腹、皆可，`drug-rules.timingText`；以前一律印「飯後」，Omeprazole、Levothyroxine 都印錯。醫師可在處方列的時機選單為這張處方另外指定，藥局處方表標「醫師指定」；示範：內科糖尿病追蹤的 Metformin 隨餐改飯後）、處方醫師、**調劑藥師**（核對的人；還沒核對就先印的話是目前登入的藥師）、調劑日。一張 1/4 A4，用最長的警語實際列印過，4 張一頁、沒有被裁掉。
- **掛號單**（`components/RegistrationSlip.vue`）：80 mm 寬（櫃台出單機），印診間與位置、看診號、就醫序號、預估應收，和病歷號的 Code 39 條碼（`utils/code39.ts`，SVG）。條碼掃描器就是「打字＋Enter」，批價、掛號的搜尋框掃了就直接選到這位病人；條碼畫出來後再反向解碼驗證過。
- **用真的列印驗證**：頁數是用無頭 Chrome 的 `Page.printToPDF` 實際產生 PDF 算出來的，不是看預覽畫面估的。

### 16. 把要做的事送到使用者面前

這一輪對照原系統（jian-HIS，比較與取捨見 `docs/jian-his-comparison.md`），逐一檢查「每個角色在自己的工作上要找多久」。原則是：使用者需要的資訊，在他做事的那個畫面上就看得到，不必換頁、捲動或自己記。

- **櫃台**：確認掛號區顯示預估應收（看完診才收錢，但要答得出「今天多少」）；病人卡上直接退掛、改期；停診待通知在掛號頁就有提示條，首頁有待辦。
- **護理師**：沒選病人時就是全病房「本班待辦」；醫師新開、停止的醫囑在病人清單上標「新醫囑」，核對後才消失；「醫囑」分頁列出長期的護理、飲食、處置醫囑（以前護理端看不到「翻身 Q2H」「禁食」）。
- **醫師**：組套一鍵帶入（個人＋科室共用）、片語簡碼展開；預防保健在看診頁就能登錄，已量的血壓身高體重帶入。
- **醫師叫號時，上一位還沒完成會先問**（`opd.startConsult`）：「第 2 號 楊佩珊（08:07 叫號）還在看診中」，可以「回到第 2 號」或「仍要叫號」（病人去檢查、等報告時先看下一位）。不硬擋；仍要叫號的寫進稽核，候診清單標「同時看診」。以前不提醒，前一位的病歷停在草稿、批價永遠等不到他。
- **藥師、批價**：清單可搜尋，批價清單直接顯示預估應收；日結列出看完診還沒批價的人。
- **帳本寫入不對外**：`postStock`（庫存唯一的寫入點）本身不檢查登入與權限，它是給進貨、發藥、盤點過帳這些已經檢查過的服務呼叫的。以前它從 `inventory.ts` 匯出，`overNetwork(inventory)` 就把它一起包成 `inventoryApi.postStock`——任何頁面都能直接改庫存。現在放在不對外的 `stock-ledger.ts`，流程測試檢查各 Api 都沒有它。**模組裡 export 的每一個函式都會變成 API**，內部用的工具不要放在對外的服務模組裡。
- **需求要算在「需要的地方」**：補貨申請是窗口缺藥、病人在門診藥局等。以前不分地點，大型醫院藥庫一到貨申請就結案，首頁不再提醒，病人在窗口還是領不到。現在只有藥進了門診藥局才沖銷（大型醫院要等撥補簽收）。
- **運送中是一個狀態，不是一個地點**：撥發時藥庫就扣、簽收時藥局才入，中間的藥不屬於任何地點（全院總量暫時少了運送中的量，庫存頁另外標「運送中」）。簽收逐批填實收、短少寫原因——全院總量最後只少了真的不見的部分，查得到是哪一張單、為什麼。
- **一般進貨走採購單，「無單進貨」要原因**：開單與核准分開（藥師開、管理員核准），到貨對品項入庫、超收擋下；緊急調貨、贈品、退藥回收這些不經採購的入庫，選原因後異動帳標「無單進貨：原因」，月底對帳查得到。
- **缺藥時，窗口只「申請補貨」**（`inventory.requestRestock`）：以前窗口的「補貨」直接開進貨單，病人在窗口等，藥師得憑空編一個批號、效期，建議量固定「缺量＋500」。現在窗口只填數量（建議量依用量算、附算式），調劑單標「已申請補貨」；同一種藥同時只有一張待到貨申請，再缺就追加、把病人加進等候名單。申請是「需求」：開採購單時勾選帶入，貨到了在採購單「到貨入庫」，入庫量自動抵掉申請（分批到貨會留著尚欠），到齊結案，等候的單就能核對。首頁有「補貨申請待到貨」待辦。
- **執行仍回到原本的畫面**：待辦清單、提示條只負責「帶過去」，給藥、核對、登錄都在原本的頁面做——把關（高警訊雙人核對、原因填寫）只寫一份。

## 已知的簡化與限制

這是展示系統，以下是刻意的簡化：

- **密碼過期太久才鎖帳號**：寬限內登入後先改密碼就能用；鎖定只看「過期幾天」，沒有「連錯幾次密碼就鎖」；以前的密碼和目前的密碼一樣以明文存在瀏覽器（真實系統只存雜湊）。
- **沒有真正的後端與資安**：密碼以明文存在瀏覽器，登入頁會列出展示帳號，匯出檔也包含密碼。權限檢查在前端的模擬服務層，可以被繞過。
- **健保規則為簡化版**：掛號費、部分負擔、預防保健資格只取主要條件，並非完整法規。
- **藥車交接是「系統逐盒點收＋紙本簽收單」**：簽收單的簽名不回寫系統（系統以「藥車待點收」的點收為準）；點收不擋給藥。送回藥局只記誰、何時送回，數量以藥師點收為準。無法逐劑換算的藥（胰島素筆）整支發、不退。
- **轉診是簡化版**：只有門診；經轉診部分負擔只分兩種金額（沒有依醫院層級、慢性病、急診的差別）；同一療程只認「醫師約的回診」；沒有電子轉診平台、健保轉診費申報，轉出的單也收不到外院回覆；本院轉他科不算轉診（用會診、預約回診）。
- **交互作用是展示用的小對照表**：只涵蓋主檔裡的藥（約 8 組交互作用、5 類同類藥），沒有接藥物交互作用資料庫，也沒有健保雲端藥歷（只比對本院的處方）；藥師看得到醫師的原因，但沒有門診處方疑義退回醫師的流程；出院帶藥的編輯畫面只比對過敏，沒有比對交互作用。
- **診斷證明書只有一種格式**：沒有英文版、甲乙種、死亡證明或其他證明文件；批價後要再開得作廢重開（不另收費）或下次看診再開，不能補收證明書費；沒有電子簽章，印出來靠醫院印信。
- **預約回診只能約同科、自己約**：沒有「醫師寫建議回診日、櫃台再掛」的流程；病人沒來（爽約）不追蹤；改期、取消照舊在櫃台辦；預約不收預收款。
- **出院帶藥是一步調劑**：藥師按「調劑完成」就扣帳，沒有門診那種另一位藥師核對；出院後要退藥走不了（請改用門診退藥流程，展示沒有串）；藥局可用量只看住院藥局，不足時要先撥補；沒有出院帶藥的自費選項（依病人身分計價）。
- **急診是簡化版**：檢傷是依台灣急診檢傷分類精神的簡化規則（常見主訴的預設級數＋幾項生命徵象），不是完整的 TTAS 主訴與判定因子；急診醫師在門診看診頁看診；留觀沿用住院的醫囑與護理（留觀床 6 床固定、沒有急診專用的護理評估與交班格式），留觀轉住院的住院日從結束留觀那天算、經營月報的入院日仍是開始留觀那天；急診收住院時急診開的藥照樣由門診藥局調劑（實務上多在急診給），退藥直接從住院帳單少算；轉院只記醫院與原因，沒有轉診單與救護車；沒有 119 到院前通報、大量傷患、急診醫師排班；急診部分負擔只分兩個金額（沒有依醫院層級、轉診、職災）。觀察床費、急診診察費點數是展示用近似值。
- **手術排程與術前核對是簡化版**：只有住院病人的排程手術（沒有門診手術、急診刀、日間手術）；手術房 3 間固定、開放時段固定，沒有麻醉科排班、手術團隊成員（助手、刷手、流動護理師）與器械包；術式只有主檔幾個常見的、一台一個術式；三段查核由護理師勾選代表團隊確認（沒有每位成員簽名）；麻醉紀錄、恢復室、術後醫囑沒有做；計數不符只記原因與處理（沒有 X 光醫令連動）；同意書只勾「已簽」、不存掃描檔。點數是展示用近似值。
- **經營月報是簡化版**：只有一家院區、一個月一份（沒有季報、年報、自訂區間）；佔床率用「目前」的病床數（沒有病床增減的歷史），住院人日以每天午夜在院計；收入是收據的應收與日結實收（現金基礎），沒有權責基礎、成本、人力與健保核刪；藥費占比只看健保申報點數；沒有目標值、預算達成率、病人來源（地區、轉診）分析；示範資料只有最近幾個月。
- **病歷影本申請是簡化版**：每一項（一次門診、一份病摘、一份報告）算一頁（實際依張數）；只有文字病歷（沒有影像光碟、護理紀錄、醫囑單、病程紀錄、手術紀錄）；精神科、性侵害、愛滋等特殊病歷沒有另外的限制，也沒有「主治醫師審閱後才能給」的流程；委託書只勾「已核對」、不存掃描檔；未成年、受監護宣告的病人沒有另外判斷法定代理人；隔天以後不能作廢也沒有退費；沒有示範資料（櫃台直接申請一次就有）。
- **輸血備血是簡化版**：只有住院；血品只有紅血球、新鮮冷凍血漿、血小板三種，沒有減除白血球／照射／洗滌等特殊處理；血型與交叉試驗只登錄結果（沒有抗體篩檢、不規則抗體、電腦交叉試驗），交叉試驗沒有 72 小時效期；血漿、血小板相容只看 ABO（Rh 陰性的人也可以輸 Rh 陽性的血小板，實際要考慮 RhIG）；新鮮冷凍血漿沒有凝血功能的檢驗門檻；發血一次一袋、沒有運送簽收與保冷箱溫度紀錄；輸血反應只記症狀與醫師處置，沒有輸血反應調查流程與通報；血袋號是院內編號（不是 ISBT 128）。點數是展示用近似值。
- **管制性抗生素審核是簡化版**：只有住院、只有主檔勾選的三支藥；先用後審，不核准或逾時都不會自動停藥（只提醒）；沒有抗生素用量統計（DDD）、全院報表與抗藥性監測；沒有微生物培養的檢驗項目，菌種是手寫；療程天數只沿著「修改醫囑」接續，停藥後另開同一種藥會重新從第 1 天算。示範資料的開立時間依病人入院時間而定，住得太近的病人不放（今天的劑量要在昨天 15:00 的每日調劑裡）。
- **隔離與 DNR 是簡化版**：沒有負壓隔離病房，空氣隔離以單人房代替；隔離不會連動醫囑（不會自動開培養檢驗、防護用品），也沒有感染管制室的全院統計與通報；同房的判斷只看類別＋原因文字，不懂菌種之間的關係；DNR 只是紀錄，沒有急救流程模組，健保卡註記只是勾選（沒有上傳）；文件只登錄要件，沒有掃描檔；門診看得到標記，但開隔離、登錄 DNR 只在住院畫面。
- **飲食與營養是簡化版**：飲食只有七種（沒有低蛋白、低脂、嬰兒配方）；管灌配方主檔只有四種、畫面不能維護（要改看種子），分次時段固定 06:00–21:00 平均分，沒有灌食機速度調整紀錄、沒有水分沖管量；營養師只建議、不開管灌醫囑（主治一鍵帶入）；伙食費一天一個價（以午餐時間的醫囑為準，不分三餐、不算入院出院當天只吃一餐），沒有家屬伴餐、自備餐；營養篩檢是簡化 NRS-2002（沒有分初篩與複篩、沒有 BMI 自動評分），只篩一次（病情變化要手動重篩）；送餐清單沒有廚房備餐量、餐盤標籤與退餐。

- **疼痛與管路是簡化版**：疼痛只有 0–10 數字量表（沒有臉譜、行為量表、疼痛部位與性質）；重評看下一筆疼痛分數，不分是不是針對那次處置；管路只有四種（沒有氣管內管、胸管、引流管、傷口），沒有 CAUTI／CLABSI 感染個案與每千管路日感染率；管路日依病人目前住的病房統計（轉床前在別病房的也算這裡）；滿 7 天、96 小時只提醒，不會自動開醫囑。
- **跌倒、壓傷風險評估是簡化版**：只有 Morse 與 Braden 兩份量表（沒有院內自訂量表、兒童用量表，也沒有譫妄等其他量表）；重評間隔固定（高風險 24 小時、其他 7 天），只有切點可調；沒有跌倒事件通報、壓傷傷口分級與照片、品質指標統計；不會自動開醫囑（翻身、營養會診由醫師開）。
- **給藥條碼核對是簡化版**：只做住院給藥（排程、PRN、臨時給藥）；沒有檢體採集、輸血、門診藥局發藥的掃描，也沒有手機／PDA 介面；藥品條碼用健保碼（實際醫院印在單一劑量藥包上，展示版不另外印藥包）；腕帶用 Code 39 一維條碼。整套系統是展示用，「示範：模擬掃描」預設開啟（安全設定可關）。
- **預約未到與出院後回診是簡化版**：未到只看最近 14 天、不改掛號狀態；沒有簡訊／LINE／語音通知，也沒有網路掛號的爽約限制與統計報表。「出院後 30 天內第一次回診比照經轉診」是依記憶簡化的規則（沒有限同一疾病、沒有看是不是同院同科），實際以健保署規定為準；同一次住院約了好幾筆時，看過診之前每一筆都先標「比照經轉診」，批價時只有最早實際就醫的那筆算。
- **住院期中繳款是簡化版**：是「先繳一部分、出院時一次算總帳扣抵」，不是分段結帳（沒有期中收據的分段明細、沒有健保住院期中申報）；最多收到當時的費用，不收入院保證金；隔天以後收錯不能作廢，只能出院結帳時退還多繳；沒有分期付款、每月自動結帳、轉院時的帳務移轉。示範資料的藥費只有最近幾天的調劑紀錄，住很久的病人藥費偏少。
- **住院結帳只在出院時算總帳**：沒有年度部分負擔上限與慢性病房的比率、沒有 DRG（診斷關聯群）與健保申報格式；住院的身分用病人的預設身分（沒有住院時另選）；出院後的住院收據不能作廢或退費；伙食費、特材、自備藥沒有做。病房費、護理費點數是展示用的近似值。
- **影像只有文字報告**：沒有影像本身（PACS）、沒有和舊片比較的連結、沒有預約排程與檢查室；心電圖只有判讀文字；放射科醫師帳號也是一般醫師角色（選單看得到門診、住院，只是沒有病人）；補充報告不能撤回；住院只有臨時醫囑的影像有報告。
- **檢驗只做「登打結果、發報告」**：沒有檢體條碼、採檢時間、收件與退件（溶血、量不足）、儀器自動傳輸、品管；參考範圍是展示用的成人值（兒童也用同一套，只分男女）；住院只有臨時醫囑的檢驗有報告（長期醫囑例如每天驗血糖沒有）；危急值只在系統內提醒（首頁、紅條），電話通知要人打；醫師確認只記「已知悉」，沒有寫處置。
- **管制藥做到雙人點班、報廢覆核、殘餘量見證銷毀、收支結存簿冊、專用處方箋、醫師使用執照與申報表**：申報表是院內整理好的表（可匯出），沒有接主管機關的申報系統、也不是官方格式；住院醫囑只檢查醫師執照，不另印專用處方箋（電子醫令、給藥紀錄與簿冊已記下病人、醫師、見證人）；專用處方箋沒有編號與第二聯、醫師簽章欄是紙本手簽；身分證號只檢查格式不驗檢查碼；種子的管制藥有 Morphine 注射與錠劑（第二級）、Tramadol、Zolpidem、Alprazolam（第四級）；口服管制藥開半顆時和注射劑同一條規則（整顆扣、剩半顆見證銷毀），沒有做「藥局剝半、另一半留著下次用」；殘餘量只處理「以調劑單位開的不是整數劑量」（0.5 AMP），沒有以 mg 開立再換算；種子的「門診調劑（每日彙總）」是整天用量，簿冊列不出病人；第二人確認只有「當場輸入帳密」一種（不能事後補簽）。
- **病房常備的簡化**：補充由藥師一步完成、不需病房簽收（送錯短少靠點班抓）；點班看得到帳上數量（不是盲盤）；常備品項沒有「退回藥局」，要移除品項得先用完。
- **庫存地點沒有權限分開**：藥師都能維護地點、改負責地點（真實醫院可能只有藥劑部主管能改）；藥庫同時只能有一個（撥補、退回藥庫都找那一個）。
- **退回藥庫的申請不保留批號**：申請、核准期間照常發藥，送出時才看批號還剩多少（少了照少的送）；核准沒有期限。藥庫簽收時仍可拒收（看實物）。待報廢區只收退回的藥，藥庫自己發現的過期品照舊用「報廢過期」。
- **供應商主檔只有基本資料**：名稱、統編、聯絡人、電話、備註；沒有付款條件、合約價、供應商可供應的品項清單（任何供應商都能買任何藥）。進價只記在採購單上，不做庫存成本計價、不產生應付帳款；「以前的進價」只算核准訂購過的單。
- **盲盤只遮藥師端**：醫師開藥選單的「可用量」照常顯示（醫師不參與清點）。
- **權限是程式設定**：角色與可做的事寫在程式碼中，系統管理頁只能檢視，不能勾選調整（原因寫在權限頁）。
- **稽核紀錄只保留最近 500 筆**（受瀏覽器儲存空間限制），「最近登入」也取自這裡。
- **藥品中文名是展示用譯名**：用通用的中文學名，不是衛福部核定的正式譯名；不收錄商品名（「普拿疼」這類習慣叫法放在只供搜尋的別名）。
- **病房用餐時間全院一套**：住院給藥依服用時機對齊早 07:30、午 12:00、晚 17:30，不能依病房或病人（例：洗腎病人改時段吃飯）調整；護理師要提早或延後給，照現有規則在給藥時間窗內給或寫原因。住院醫囑的服用時機開立後不能改，要停掉重開。
- **Chrome 無痕視窗關閉後資料就消失**：無痕模式下一切功能正常，但瀏覽器在視窗關閉時清掉儲存的資料。網站無法可靠地偵測無痕模式，所以沒有提示。（儲存空間已滿、或瀏覽器完全不允許儲存時，畫面上方會一直顯示警告，並說明是哪一種原因。）
- **優免核准沒有限制連錯幾次**（每次失敗都寫稽核）；送簽沒有通知（主管要看首頁），核准只限當天；掛號頁的預估應收不含優免（優免在批價時才決定）。
- **權限只涵蓋 20 項操作**：其他動作仍是程式裡寫死的角色（`requireUser`）；頁面能不能進入照路由固定；「停診、代診」固定給管理員（排班只在系統管理頁，櫃台沒有畫面，開放給櫃台組長要先把停診搬到掛號頁）。
- **掛號預收是選填、整筆的**：掛號時可以先收一筆（預設預估應收），批價扣抵、多退少補；沒有欠卡押金，預收款也不能轉給別次就醫用。錢不夠可記欠款（只限現金）。部分退費只有退藥與檢驗處置「未執行」兩種（整項標，不能只退部分數量；只有門診——住院處置不經批價），退款依原付款方式、不能改用別的方式退。
- **只有長期給藥醫囑能「修改」**：劑量、頻率、途徑、服用時機可以改；換藥、臨時醫囑、護理／飲食醫囑請停止後另開。修改在資料上仍是停止與新開兩筆。
- **片語沒有組套快捷鍵**：範圍是個人、科室（醫師）、病房（護理師）、全院（醫師、護理師各一組，只有被指定的人能改）；全院片語沒有「醫護共用」的一組；護理站「補記反應」那一行小欄位不展開片語。病房共用片語跟著「目前所在的病房」，帳號沒有綁定所屬病房。
- **報表區間最長一年**：再長要分段查詢；超過兩個月畫面只列依月份小計（每日小計在匯出的 Excel、CSV）。Excel 只做這兩份報表（收費報表、管制藥簿冊），只有文字、數字、粗體、凍結表頭——沒有公式、框線、數字格式（金額不顯示千分位）、列印設定。
- **會診看摘要、不收費**：會診醫師看的是會診單附上的病人摘要，不能打開完整病歷；住院會診在範圍內可以開醫囑，但只能停止（不能在畫面上修改）自己開的；門診會診是書面的（不替病人掛號、會診醫師不能開門診處方），沒有會診費。「同科醫師都能寫」沒有細分值班表（同科任何醫師都算）。新科只能整筆接受或婉拒轉科。轉床只能選空床。
- **處方箋有效期只提醒不擋**：逾期的單在藥局清單標「處方逾期」、調劑單上方有提醒，照常可發（是否請醫師重開由藥師判斷），發藥稽核註明「處方已逾有效期」。慢箋每次調劑也套同一個 3 日規則（從登記領藥那天算），沒有另外處理。
- **調價沒有記錄健保發文號**：藥價、醫令點數、掛號費、部分負擔都有生效日，但只記誰、何時設定；部分負擔是整組參數一起排定（不能只排其中一項的日期）。就醫身分的「免部分負擔」「自費身分」是分類，改了立即生效。
