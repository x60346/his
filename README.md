# HIS 展示系統

醫院資訊系統（Hospital Information System）的**前端展示版**。不串接後端，所有資料由瀏覽器內的模擬層產生與保存，打開就能完整操作門診、住院、藥局、護理、預防保健與系統管理。

> 所有病人、醫師、病歷皆為虛構。這是教學與展示用的系統，**不可用於真實醫療情境**（見文末〈已知的簡化與限制〉）。

技術：Vue 3、TypeScript、Pinia、Vue Router、Tailwind CSS、Vite。不使用 UI 套件，所有元件自行實作。

**線上展示：https://x60346.github.io/his/**（每次推送到 `main`，GitHub Actions 會先跑流程測試與建置，通過後自動部署，見 `.github/workflows/deploy.yml`）

## 快速開始

需要 Node.js 18 以上。

```bash
npm install
npm run dev          # 開發伺服器 http://localhost:5180
```

| 指令 | 用途 |
|---|---|
| `npm run dev` | 開發模式 |
| `npm run build` | 型別檢查 + 正式建置（輸出到 `dist/`，可放在任何靜態主機或子目錄） |
| `npm run preview` | 預覽建置結果 |
| `npm run typecheck` | 只做型別檢查 |
| `npm run smoke` | 流程測試：在 Node 中直接呼叫服務層，跑完整就醫流程與各項規則（1227 項） |

### 展示帳號

密碼皆為 `1234`，登入頁右側可直接點選帳號快速登入。右上角「變更密碼」改過的帳號，快速登入只帶入帳號（標「已改密碼」），「重置展示資料」可還原。

| 角色 | 帳號 | 可以做的事 |
|---|---|---|
| 系統管理員 | `admin` | 檢視所有頁面；帳號、權限（在規則內調整，可指定給個人；示範：`clerk02` 被指定「優免核准」）、科別醫師、排班、收費、主檔、稽核、展示資料。**不能執行臨床操作** |
| 醫師 | `dr01` – `dr09` | 門診看診、住院醫囑、病程紀錄、預防保健 |
| 護理師 | `nurse01`、`nurse02` | 掛號、住院報到、護理站（給藥、生命徵象、護理紀錄、交班）、預防保健 |
| 藥師 | `ph01`、`ph02` | 門診調劑發藥、補貨申請、藥品庫存（採購單開單與到貨入庫、無單進貨、盤點單、報廢）；盤點單由沒清點的另一位藥師（或管理員）覆核 |
| 掛號批價 | `clerk01` | 掛號、病患資料、批價收費、住院報到（`clerk02` 是櫃台組長：可核准優免） |
| 護理師＋掛號批價 | `staff01` | 多角色帳號（小診所跟診兼櫃台）：登入時選角色，右上角切換 |

### 展示資料

- 第一次開啟時自動產生，**以「今天」為基準**：今日候診、住院第幾天、給藥排程都和當下時間連動。
- **今天走到哪一步，看建立資料時是幾點**：上午 07:30 起掛號、08:30 起叫號，下午 13:00 起掛號、13:30 起叫號，每位約 12 分鐘；時間還沒到的步驟就還沒發生。清晨建立的資料像真正的一天開始——今天的掛號都是前幾天預約的、還沒有人看過診；要看完整的「忙碌的一天」（待批價、待領藥都有），請在上午十點後按「重置展示資料」。
- 隔天再開會提示資料已過期，可一鍵「重置為今天」（系統管理 → 展示資料，或頂端提示列）。
- 可匯出成 JSON，在其他電腦匯入，重現同樣的展示情境。

## 建議的展示路線

**門診（約 5 分鐘）**

1. `clerk01`「掛號作業」：搜尋病人 → 選診次 → 掛號（可勾「掛號時預收」先收一筆，批價時扣抵、多退少補；退掛當場退還）。確認區顯示預估應收；符合資格的預防保健項目可一併勾選。今天的現場掛號預設「同時報到」；電話預約取消勾選，病人到院時在清單或病人卡上按「報到」（下午家醫科 1 號是前兩天預約、還沒到的示範病人）。病人卡上的預約可直接退掛或改期；診次卡的「名單」看該診有誰。
2. 該診的醫師（例如家醫科 `dr01`）「門診看診」：叫號（未報到的病人會先確認）→ 看診頁由上而下依 S→O→A→P 排列（頂端有前次就診摘要：「同前次」帶入診斷、藥品、處置、評估與計畫，或「只帶處方」），在醫令段套用組套（例：「上呼吸道感染」；內科 `dr02`、`dr03` 另有共用的「糖尿病追蹤」）→ 完成看診；S／O／A／P 輸入「.簡碼」再按空白鍵展開片語（`dr01`：`.uri`、`.wnl`、`.fu`）；「完成並叫下一位」（Ctrl+Enter）一次叫好下一號。開到過敏藥物會跳警示；掛了預防保健的病人可直接在看診頁登錄，本次量的血壓身高體重會帶入。
3. `clerk01`「批價結帳」：清單上就看得到預估應收 → 收款 → 印收據。身分選錯可在收費前更正。錢不夠時勾「差額記為欠款」並寫原因，照常結帳領藥；舊欠款在批價頁列出、可分次收回（掛號頁只提醒，不擋掛號；示範病人：林俊傑 100005）。「日結報表」列出看完診還沒批價的病人，實收＝應收 − 新欠 ＋ 收回；按「本月」「上月」看區間報表（依日期小計），「匯出 CSV」給會計用 Excel 開。優免選「專案減免」要填原因並**主管核准**：按「主管核准」，由 `clerk02` 輸入自己的帳密（打錯會寫進稽核；不能是結帳的櫃台本人），收據印出核准人。
   - **慢箋領藥**（不看診）：病人卡片上列出慢性病連續處方箋與可領期間，按「登記領藥」→ 直接到批價（不收掛號費、診察費、部分負擔，通常 0 元）→ 藥局。示範病人：周婉婷 100020（今天可領第 2 次）。
4. `ph01`「門診藥局」：輸入領藥號按 Enter → 核對處方 → 發藥（依效期先後扣庫存）→ 列印藥袋。前幾天沒領的單會帶到今天的清單。

**住院（約 5 分鐘）**

1. `nurse01`「住院中心」：待報到病人 → 報到配床（符合床等的空床會亮起）。
2. 主治醫師「住院醫囑」：開立長期或臨時醫囑。長期給藥醫囑會自動產生給藥排程，高警訊藥品需再確認。口服藥的給藥時間依服用時機對齊病房用餐（飯前 07:00、飯後 08:00…），可為這筆醫囑另外指定時機，對話框下方預覽每天幾點給。示範：糖尿病病人的 Metformin 醫師指定飯後（08:00、18:00）。
3. `ph01`「住院藥局」：下午做「每日調劑」（明天整天的劑量，一位病人一區，按「全部調劑」）；當天新開的醫囑列在最上面「補調劑」。胰島素筆這種無法逐劑換算的藥要填發幾支（床邊已有填 0）。調好的藥在「待核對」逐位病人核對：「核對送出」才扣住院藥局、送病房，發現錯誤「退回重調」（雙人核對設定開啟時，要換 `ph02` 核對）。病房送回的藥在「待退藥點收」點收入庫（短少寫原因）；還沒送回的另外列出供參考。核對送出後，`nurse01` 在護理站「本班待辦」的「藥車待點收」逐盒點收；有問題的按「不符」（短少、破損、不是這位病人的），藥局頁最上面出現「病房回報」，藥師處理時可逐行補發（從住院藥局扣）並寫說明。點收前照樣可以給藥，給藥列標「藥車未點收」；交班分頁會提醒還沒點收的藥車。
4. `nurse01`「護理站」：沒選病人時是全病房「本班待辦」，點一列就到該病人；上方「待送回藥局」列出沒給的 UD 藥（暫停、拒絕、停止、出院病人的剩藥），勾選後「送回藥局」。醫師新開或停止的醫囑會標「新醫囑」，在「醫囑」分頁核對。依時間給藥（逾時標紅、太早不能給；藥局還沒調劑、或還在核對的標「待藥局調劑」「藥局核對中」，不能給；PRN、STAT 用病房常備，給藥時直接扣住院藥局）、記錄生命徵象（看趨勢圖）、Focus DAR 護理紀錄、交班（顯示最近三班，跨午夜不會消失）。
5. 片語在住院也能用：醫師的病程紀錄、出院病摘（`dr02`：`.stable`、`.cont`、`.opdfu`），護理師的護理紀錄、交班（`nurse01`：`.fall`、`.fever`、`.vs`）；欄位下方「管理片語」可新增修改。片語有個人的與共用的：醫師的**科室共用**（內科 `dr02`、`dr03` 都能用 `.dmedu`；`.htn` 兩人都有，`dr02` 展開的是自己的個人片語——同簡碼個人優先，管理畫面標「被你的個人片語蓋住」），護理師的**病房共用**跟著護理站目前選的病房（5A：`.turn`、`.iv`；換到 6B 就沒有）。共用片語同科／同病房的人都能改、能刪，記下最後修改的人。
6. 會診與轉科：主治醫師在「住院醫囑」按「會診」開會診單（科別、目的、可勾急會診）；會診科醫師首頁待辦「待回覆會診」、病人清單上方打開，看會診單附的病人摘要後回覆評估與建議，可勾「建議轉本科」（示範：外科 `dr04` 有一張糖尿病病人左足傷口的會診；肺炎病人的耳鼻喉科會診已回覆）。主治看到建議轉科就按「依會診申請轉科」，科別、醫師、原因都帶好。申請轉科要寫**轉出摘要**（住院經過、目前問題必填）；新科醫師首頁待辦「轉入申請」，在病人清單上方打開 → 逐筆決定原醫囑延續或停止、可一併轉到本科病房的空床 → 接受（或寫原因婉拒）。示範：腦梗塞的病人已申請轉復健科，用 `dr09` 登入就能接受。
7. 主治醫師在「住院醫囑」的「出院病摘」分頁寫病摘（可存草稿），「簽署並准予出院」後，床位圖與護理站標「准出院」；病人狀況變了可取消（內容留成草稿）。
8. 「住院中心」辦理出院（醫師沒簽署不能辦）→ 核對醫師的病摘、確認未執行項目 → 醫囑停止、未執行排程刪除、病床轉為清潔中。病摘之後在「病患資料」的「住院紀錄」查閱。示範：5A 病房有一位已准出院的病人。

**其他值得看的**

- 「系統管理 → 排班 → 單日調整」：停診（病人退掛＋通知名單）與代診（掛號轉給同科醫師）。通知名單櫃台在掛號頁就看得到，首頁也有待辦。
- 「藥品庫存」：每一筆庫存增減的異動帳、批號效期、盤點。**大型醫院**（系統管理 → 展示資料，重置時選「大型醫院」）有藥庫、門診藥局、住院藥局三個地點，頁面頂端選「目前地點」；多一個「撥補單」分頁：藥局「向藥庫請領」（需求清單列出低於該藥局安全庫存的藥與門診藥局的補貨申請）→ 藥庫撥發（依效期先到先出，可少撥，運送中）→ 藥局逐批簽收才入帳（短少寫原因）。反方向「退回藥庫」：藥局逐批勾選要退的批號（過期、近效期、存量偏多的排前面），寫原因送出就扣帳、運送中 → 藥庫簽收時逐批選「入庫」「待報廢」（放進藥庫底下的「待報廢區」，過期的只能這樣）或「拒收退回」（寫原因，帳回到原藥局）；「待報廢區」分頁可以報廢或把沒過期的放回可用。首頁待辦「撥補待撥發」「撥補待簽收」；示範：藥庫有一張請領中的單（Cephalexin 藥庫缺貨只能撥 0、Acetaminophen 可撥）。藥品明細可改「這個地點」的安全庫存。「補貨待到貨」卡片列出已申請、還沒到貨的藥（有病人在等的排前面）。示範：Cephalexin 有一張昨天的申請，已列入待核准的採購單。
- 「藥品庫存 → 採購單」：`ph01`「開採購單」→ 選供應商（主檔裡往來中的；勾需求清單時自動帶上次買這種藥的那家，每一行提示「這家上次 X 元」）→ 從需求清單（待處理的補貨申請＋低於安全庫存的藥，附建議量、上次供應商與進價）勾選帶入 → 送出 → `admin` 首頁待辦「採購單待核准」→ 核准（或退回寫原因）→ `ph01` 對品項「到貨入庫」（批號效期照實物，可分批，超收擋下）→ 全部到齊自動「已到齊」；短交可結案。沒有採購單的入庫用「無單進貨」，要選原因。「供應商」分頁維護主檔（藥師、管理員都能改），點一家看「以前的進價」與其他供應商比價（較便宜的標橘色）；示範資料有一家已停用。「庫存地點」分頁新增、改名、停用地點，並指定門診發藥、住院調劑、採購入庫由哪裡負責（大型醫院示範：新增「急診藥局」→ 門診發藥改由它負責，醫師開藥看到的可用量就變成它的）。
- 「藥品庫存 → 盤點單」：`ph01` 建立（全部／劑型／指定藥品）→ 照架上實物填數量（**看不到帳上數量**；庫存頁、明細、調劑畫面這段期間也只顯示「盤點中」）→ 送出 → 換 `ph02`（或 `admin`）登入，看差異、寫原因後覆核過帳，或退回重盤。可列印清點表（不印帳上數量）、加「架上有、表上沒有」的批號。
- 「系統管理 → 收費設定」：調整部分負擔時右側即時試算；已開立的收據不受影響。部分負擔、掛號費（就醫身分）、醫令點數（主檔）都可以填「生效日」排定某天起調整，清單標「12/01 起…」；批價依看診日，生效日前看診、之後才批價的照舊價。
- 「系統管理 → 主檔 → 藥品」：編輯價格時填「價格生效日」（例：下個月 1 日），清單會提示「12/01 起 2.2」；批價依**看診日**的價格（示範：Metformin 已排定下個月調價、Amlodipine 3 天前調降，更早的收據是舊價）。
- 用 `admin` 進入任何臨床頁面：可以看，但操作會被擋下。

## 架構

```
types        資料長什麼樣子（src/types）
  ↓
codes        固定的代碼與主檔初始值（src/mock/codes.ts）
  ↓
mock db      模擬資料庫：記憶體 + localStorage，種子資料（src/mock）
  ↓
services     模擬後端：所有規則、權限、交易都在這一層（src/services）
  ↓
components   UI 元件：只負責呈現，不知道業務（src/components）
  ↓
pages        頁面：組合元件、呼叫服務、處理使用者互動（src/pages）
```

**唯一的規矩：只有 services 可以碰資料庫。** 頁面一律 `import { xxxApi } from '@/services'`。

```
src/
├─ types/            領域型別
├─ mock/             codes（代碼）、db（資料庫與版本）、seed（展示資料）
├─ services/
│  ├─ http.ts        query / mutate（延遲、交易、回滾、複本）、requireUser、audit、failFields / fieldErrors（欄位錯誤）
│  ├─ *-rules.ts     純函式規則：資格與欄位格式、護理時間窗與班別、醫囑異動、庫存 FEFO 與狀態標籤、劑量與天數、藥品同名、候診順序（計費規則在 billing.ts）
│  ├─ views.ts       查表、組合檢視資料（後端的 JOIN + DTO）、usable（可開立檢查）
│  └─ 各業務模組      booking、opd、orderset（組套）、charge、pharmacy、inventory、admission、ipd、nursing、prevent、schedule、admin…
├─ composables/      useQuery、useAction、useDebounced、useClock（共用時鐘）、useRevealOnNarrow
├─ stores/           auth（登入者）、ui（提示與確認框）
├─ utils/            日期、代碼標籤、身分證驗證、clonePlain、safeRedirect
├─ components/ui/    UButton、UTable、UDialog、USearchSelect、UQueryState、ULineChart…
├─ layouts/          主版面（選單由路由表與權限自動產生）
├─ router/           路由表：頁面、選單、權限的單一來源
└─ pages/            各功能頁
scripts/smoke-flow.mjs   流程測試
```

## 設計原則

這個專案是一頁一頁做出來的，每一頁都踩過坑。以下是整理出來的原則，每一條都附上程式中的對應位置。

### 1. 規則放在服務層；頁面的判斷只是為了體驗

頁面可以先判斷（勾不了不符資格的項目、按鈕反灰），但**服務層一定要再判斷一次**，因為頁面擋住的只是誠實的使用者。

- 掛號頁只列出符合資格的預防保健項目，`booking.register` 仍用同一個 `checkEligibility` 再檢查。曾經漏掉這一步，結果直接呼叫 API 就能讓男性掛子宮頸抹片，還會以 A3 案件申報。
- 給藥按鈕在「還沒到時間」時反灰，`nursing.executeMar` 一樣會擋。
- 「能不能掛號」由服務層算好 `SessionView.bookable`，頁面不自己組 `full || closed || suspended`。

### 2. 規則寫成純函式，所有人共用

同一條規則只寫一次，服務層、頁面即時提示、種子資料、測試都呼叫它，就不會各算各的。

| 住院給藥時間 | `drug-rules.marTimes`：一天幾次的頻率（QD／BID／TID／QID）對齊病房用餐（早 07:30、午 12:00、晚 17:30）——飯前提前 30 分、飯後延後 30 分、空腹提前 1 小時、隨餐就是用餐時間；BID 早晚、QID 第 4 次在睡前 21:00。飯前飯後皆可、間隔型（Q6H／Q8H／Q12H）、睡前、非口服照頻率的固定時間。`ipd.ensureMar` 與種子都只呼叫它（流程測試掃描）；開醫囑對話框預覽每天幾點給 |
| 供應商主檔 | `purchase-rules.taxIdProblem`（統一編號 8 碼＋檢查碼：加權 1,2,1,2,1,2,4,1、乘積位數和能被 5 整除，第 7 碼是 7 的特例），主檔表單即時提示與服務層同一條；`normalizeSupplierName` 比對同名（含停用的——停用的請直接啟用，兩筆同一家進價紀錄就分散了）。採購單只能選啟用中的，存供應商 id 與**開單時的名稱**（單據是文件，供應商改名舊單不變）；還有進行中採購單的不能停用。「以前的進價」（`supplierPrices`）：每種藥這家最近一次＋其他供應商最近一次，只算核准訂購過的單（待核准可能被退回） |
| 建議補貨量 | `stock-rules.suggestRestockQty`：（等候中的處方 − 現有 − 已申請未到貨）＋安全庫存＋14 天用量，進位到 10；對話框顯示算式，種子資料也用它 |
| 預防保健欄位格式（血壓、血糖…）與 BMI | `prevent-rules.FIELD_FORMATS`、`calcBmi`：BMI 由身高體重算，不讓人填 |
| 藥品同名判斷 | `services/drug-rules.ts`（`sameNameDrugs`、`needsSameNameCheck`） |
| 過敏比對 | `services/allergy.ts` |
| 劑量合理性、處方天數 | `services/dose-rules.ts` |

**防打錯的規則看「倍數」，不看絕對值。** 各藥的劑量刻度差很多（1 顆錠劑對 10 U Insulin），所以劑量以「該藥常用劑量的幾倍」判斷：超過 3 倍（高警訊藥品 2 倍）要醫師確認，超過 20 倍幾乎一定是多打了 0，直接擋下。處方天數限 1–30 天，收款找零上萬元視為輸入錯誤。這些不是臨床上限，而是攔住「多打一個 0」的防線，門診、住院、頁面即時提示都呼叫同一個函式。

**規則是程式，參數是資料。** 部分負擔的金額可以在系統管理調整，計算方式不行；預防保健項目可以調整間隔與欄位，但不能在畫面上新增項目，因為新項目代表新的資格邏輯。

### 3. 每一種檢查只有一個入口

規則散落在各處，就會出現「門診有檢查、住院沒檢查」。

| 檢查 | 唯一入口 |
|---|---|
| 登入 | `query()` 預設必須登入，公開的要明確寫 `{ public: true }` |
| 角色 | `requireUser(...roles)`，管理員也不會自動通過 |
| 誰能看到什麼資料 | 在服務層決定、不是在畫面上藏：首頁「今日收入」只回傳給掛號批價與管理員，其他角色的 `getDashboard` 根本不含這筆資料 |
| 主檔停用 | `usable.drug / procedure / icd`：開立新單一律經過它，顯示舊紀錄則用 `find` |
| 庫存異動 | `inventory.postStock`：唯一能改庫存的函式 |
| 建立掛號 | `booking.createVisit`：掛號與改期共用，改期不能繞過診次、重複、預防保健資格任何一條 |
| 「同一份名單」的範圍 | 停診待通知 `schedule.suspendNoticeVisits`（名單與首頁待辦）、預防保健已登錄 `prevent.visitItems`（工作清單與看診頁）、待領藥 `pharmacy.awaitingPickup`（藥局清單與首頁）——兩個地方顯示的數字，用同一個函式算（流程測試比對兩邊相等） |
| 登入後導向 | `utils/redirect.ts` 的 `safeRedirect`：路由守衛與登入頁共用；只接受站內路徑（拒絕 `//`、反斜線、外部網址），權限仍交給守衛 |

### 4. 寫入是交易；回傳的是複本；參數經過「網路」

`services/http.ts` 的 `mutate()` 先拍快照，失敗就整個回滾，不會留下改到一半的資料；成功時先複製回傳值，再存檔。`overNetwork()` 讓所有參數經過 JSON 序列化，模擬真實後端只收得到純資料，頁面的 Vue Proxy 不會被存進資料庫。

- **存檔失敗也是交易失敗**：`mock/db.ts` 的 `commit()` 寫不進 localStorage（通常是空間已滿）時丟出錯誤，由 `mutate()` 回滾並告訴使用者。以前是默默吞掉，畫面顯示收款成功、給了收據號，重新整理後資料卻不見了。
- **讀取時順便產生的資料例外**：診次、給藥排程這類「查詢時才補產生」的資料用 `commitIfPossible()`，存不進去也不影響這次查詢，下次會再產生；使用者的操作一律走 `mutate → commit`。
- **頁面層要複製資料用 `clonePlain`**（`utils/clone.ts`）：頁面的資料常是 Vue 的 Proxy，`structuredClone` 複製不了會直接丟錯（病患資料頁按「修改」曾因此打不開）。頁面資料都是純資料，用 JSON 來回一次，和 `overNetwork` 同一個道理。

### 5. 狀態機

狀態的轉移都在服務層檢查，不能跳步：

- 掛號：已掛號 → 看診中 → 已看診 → 已批價 → 已領藥（或已退掛）
- 調劑：待調劑 → 已核對 → 已發藥
- 住院：預約 → 住院中 → 出院（或取消）
- 病床：空床 → 使用中 → 清潔中 → 空床（或保留）
- 給藥：待給 → 已給／暫停／拒絕

### 6. 紀錄只能增補，不能改寫

- 庫存是**帳本**（`StockTxn`）：每一筆增減都有時間、人、單據、原因與結存；`drug.stock` 只是快取，測試會驗證它永遠等於帳本加總。主檔維護不能順手改庫存。
- 護理紀錄的「反應（R）」、預防保健的「待報告」只能補一次，補完就定案。
- 收據保存開立當時的明細，日後調整收費設定，舊收據不會變。
- **藥價看「看診日」，不是「批價日」**：調價日之前看診、之後才來批價的，收看診那天的價格（健保申報也依就醫日）；否則同一天看診的兩個人，會因為誰先結帳而價格不同。主檔的 `nhiPrice` 是最早的原價，之後的價格存在 `priceChanges`，**任何地方要價格都用 `drugPriceOn`**（流程測試掃描批價原始碼，不得直接讀主檔價格）。生效日不能早於今天：回溯調價會悄悄改掉已看診、還沒批價的人的金額。
- 稽核紀錄沒有任何修改或刪除的 API。
- **登錄錯了用「作廢」，不是改或刪**：預防保健紀錄作廢（`voidPreventRecord`）只加上原因、時間、作廢人，原內容不動；作廢後不佔資格、不計統計，可以重新登錄正確的一筆。
- **換人負責要留下經過**：變更主治醫師（`changeAttending`）把「誰、何時、從誰換成誰、為什麼」附加到 `attendingHistory`。
- **狀態可以改回去，歷史留在稽核**：停診通知的「已通知」可以撤銷（`unmarkNotified`），稽核紀錄記下原本是誰、何時記錄的。
- **改期不是改掛號，是退舊掛新**（`rescheduleVisit`）：原掛號留下「改期至 日期 診別 科別 醫師 第 N 號」，新診次掛不上就整筆回滾。
- **身分更正只限收費前**（`correctIdentity`）：已開收據的要先作廢，因為收據存的是當時算好的金額；稽核記下前後身分與原因。
- **核對醫囑留下是誰、何時**（`ackOrders`）：只核對畫面上看得到的那幾筆——醫師剛好又開的新醫囑，護理師還沒看到就不能被一起簽掉。可以逐筆核對，也可以「全部核對」（交班常用）。
- **有疑問就退回醫師，疑問期間暫停執行**（`queryOrder`、`replyOrderQuery`）：護理師寫疑問後，那筆醫囑不能核對（整批核對自動跳過）、給藥與臨時醫囑的執行暫停（`holdForQuery`，排程給藥、PRN、臨時醫囑共用一條）；緊急時可寫原因強制執行，記在給藥紀錄與稽核。醫師在病人清單「疑問 N」、首頁待辦看到，回覆「確認無誤」（寫說明）後護理師要看到回覆再核對一次；要改劑量、頻率、途徑、時機就按「修改醫囑」（`reviseOrder`）：畫面一步，資料上仍是「停止舊的＋開新的」兩筆、互相標記（已給的藥掛在舊醫囑上，直接改舊醫囑的劑量會讓以前的給藥紀錄看起來像照新劑量給的）；檢查與開新醫囑共用 `createOrder`；疑問記為「已修改」並自動寫出改了什麼。**從下一劑開始**：新醫囑的起始時間取「現在」與「舊醫囑最後一劑已處理的時間」較晚者——12:00 那劑提早在 11:40 給了、11:55 改劑量，不會在 12:00 再排一劑。換藥則停止那筆（疑問記為「已停止此醫囑」）再另開。疑問與回覆可以多輪，全部留在醫囑上。
- **補登不是改寫時間，是兩個時間都留**：先給藥、後登打時，`executedAt` 記實際給藥時間、`recordedAt` 記登打時間，畫面顯示「13:05（13:51 補登）」。補登時間不能晚於現在、不能早於可給藥時間（和「太早不能給」同一條 `marUrgency`）、最多往前 2 小時（`nursing-rules.checkGivenAt`）。
- **保留床一定是保留給某個人**（`Bed.reservedFor`）：那位病人報到時可以直接選這床；預約取消或報到在別床時，系統自動解除保留並寫稽核——不會有沒人知道為誰保留、永遠佔著的床。
- **出院不能把沒給的藥一起刪掉**：出院前先列出逾時未給的藥、未執行的臨時醫囑（`dischargeCheck`），要勾選確認才能出院（服務層也擋）；逾時未給的藥改為「暫停：出院時未給藥」留在紀錄上，只有還沒到時間的排程才取消——以前一律刪除，紀錄上就像從來沒排過。
- **醫囑停止、完成都要有時間**：`stopAt` 是「新／已停／已完成」判斷的依據，流程測試檢查每一筆非執行中的醫囑都有它（曾經漏在臨時給藥與種子資料）。

### 7. 被引用過的只能停用，不能刪除；動手前先看會影響誰

- 科別、醫師、藥品、醫令、診斷碼都只能停用。停用前會列出還在用它的資料（未看診掛號、住院病人、排班、執行中醫囑）。
- **例外：個人設定可以刪除**。組套（`orderSets`，個人或科室共用）、片語（`phrases`）不是醫療紀錄、也沒有被別的資料引用，刪除只寫稽核。組套裡的藥日後停用了，**套用時才檢查**（`expandOrderSet` 濾掉並列出），存的時候能開不代表半年後還能開。
- **科室組套大家都能改，就要看得出是誰改的**：同科在職醫師都能套用、覆蓋、刪除（`orderset.canUse`：個人的看 doctorId、科室的看「目前」所屬科別，轉科後就看不到原科室的），每次存檔記下 `updatedBy`，清單標「最後修改 黃柏翰 11/10」，覆蓋前的確認也說出上一位修改的人；稽核寫明「內科科室組套」。個人與科室可以同名（選單用分組分開）。
- **片語展開不能吃掉醫師打的字**：規則在 `phrase-rules.expandPhrase`——游標前緊接著「.簡碼」、而且前面是開頭／空白／中文標點才展開（「3.5mg」不會），找不到的簡碼原樣保留、照常輸入空白；**中文輸入法選字時（`isComposing`）按空白是在選字，不攔**；Shift+Tab 不攔。只有真的展開時才 `preventDefault`，所以一般的 Tab 照常跳到下一欄。按鍵處理只有一份（`composables/usePhrases`）：門診 SOAP、住院病程與出院病摘、護理紀錄、交班都用它（流程測試掃描頁面不得自己呼叫 `expandPhrase`）。
- **共用的東西不能蓋掉個人的習慣**：片語同簡碼可以個人與共用並存，個人的優先——順序由服務層決定（`phrase.listPhrases` 個人在前），`expandPhrase` 取第一個符合的，頁面不另寫判斷；被蓋住的共用片語在管理畫面標出來，不然有人改了共用的 `.htn`、自己卻怎麼打都是舊句子，會以為壞了。護理師的病房共用片語看「目前所在的病房」（`usePhrases(() => 病房)`），不綁帳號：支援別的病房時用的是那個病房的說法。
- **把舊內容帶進新處方，只有一個入口判斷停用**：組套、「同前次」、「只帶處方」都經過服務層的 `pickUsable`（`src/services/views.ts`），停用的藥、處置、診斷碼濾掉並告訴醫師；頁面的合併規則也只有 `mergeIntoDraft` 一份（重複的略過、診斷與 S／A／P 只填空白的）。以前從歷史複製處方沒有過濾，停用藥要到完成看診才被擋。
- **「同前次」不帶 S 主訴、O 客觀、生命徵象**：那是本次的事實，照抄上次的（例如「無發燒」）會讓病歷與實情不符；只帶診斷、藥品、處置、A 評估、P 計畫（`expandEncounter`）。前次是慢箋調劑（不是看診、沒有評估計畫）時，改帶原處方那次看診。
- 停診時已掛號的病人不能就這樣消失：會退掛，並進入「停診通知」名單，直到逐一電話通知完成。
- 修改每週排班只影響還沒有人掛號的未來診次。
- 管理員不能停用自己、不能拿掉自己的管理員角色；系統至少保留一個啟用的管理員（縱深防禦）。

### 8. 畫面上的資料，要和它依據的來源保持同一個版本

- **BFF**：需要多份資料的畫面，由服務層一次組好回傳，例如 `getChargeDetail`、`getMarBoard`、`getPreventProfile`、`getDrugLedger`、`getSessionImpact`，避免各自查詢、彼此不同步。
- **id 比對**：切換病人時，查詢結果帶著「這是誰的資料」，id 對不上就不顯示，舊病人的資料不會閃過新病人的畫面。
- **只存 id，不存快照**：從清單點進明細時，只記 id，資料每次從最新清單取得。
- **載入中不等於沒有資料**：`UQueryState` 統一處理載入、空、有資料三種狀態；`USearchSelect` 在防抖等待時也算「搜尋中」。

### 9. 時間是資料的一部分

- **全系統只有一個時鐘**：`composables/useClock.ts` 一個計時器、每 30 秒更新，所有頁面讀同一個「現在」與「今天」（`useNow` 是它的舊名稱）。「逾時、待給、太早」依它即時計算（＋`marUrgency`）。
- **「今天」會走動**：頁面打開時記下 `today()` 就不會再變，開著跨過午夜，護理站還停在昨天，而大夜班正是跨夜的人。`followToday(date)` 讓日期欄位跟著新的一天走；使用者自己選了別的日期（例如查昨天的日結）就不去動它。
- 「每 N 年」定義為同月同日（`addYears`，2/29 會進位到 3/1），不用 N × 365 天。
- 帳本依寫入順序排序，不依時間排序：時間只到分鐘，同一分鐘的兩筆分不出先後。同樣的道理，「最新一筆生命徵象」同一分鐘有兩筆時取後寫入的（曾經取到舊值）。
- **交班屬於「班」，不屬於日曆日**：11/10 的小夜常在 11/11 00:10 才寫完交班，它仍是「11/10 小夜」（`shiftInstanceOf`）。交班清單顯示最近三班，不是「今天」——以前依今天查，大夜 00:15 就看不到小夜 23:45 寫的交班。
- **沒做完的工作要跨日帶著走**：藥局「待調劑」包含前幾天開立還沒領的單（標日期，領藥號每天重編）；「已發藥」依發藥時間算，不是開立日。
- **「本班待辦」的範圍跟著班走**（`shiftRange`）：逾時、可給的給藥一律列出（含 15:30 時已可提早給的 16:10），還沒到時間的只列到本班結束——和病人清單的徽章是同一個範圍。

### 10. 種子資料也要守規則

展示資料不能違反臨床常識，否則展示時就在示範錯誤。

- 開藥避開病人的過敏藥物（`checkAllergies`），預防保健紀錄都符合資格（`checkEligibility`）。
- 成人病房只住成人；小兒科只看 13 歲以下、婦產科只看女性（`deptFits`）。
- 庫存帳用與服務層相同的 FEFO 規則依時間順序「重播」產生；不足時直接報錯，不默默略過。
- 時間軸要合理：掛號 ≤ 叫號 ≤ 完成看診 ≤ 批價 ≤ 發藥；看診號、收據號、領藥號、就醫序號都依時間先後（資料分段產生，最後統一依時間重編）。以前過去的就醫會「還沒看完就先付錢」，收據號 R0002 比 R0003 晚。
- 不能有晚於「現在」的時間（早上 8 點不該已經有 10:30 的發藥紀錄；清晨開啟時，當天 08:30 的查房紀錄也不能先出現）。
- 展示用的住院醫囑都視為「之前開的、已核對過」——否則一打開護理站，每位病人都掛著「新醫囑」，真正新開的反而被淹沒。
- 流程測試會逐一驗證以上幾點；測試裡的檢查是**另外獨立寫的**，不重用種子資料裡的函式。

### 11. 多分頁：資料共用，登入身分各自獨立

| 存什麼 | 存在哪 | 範圍 |
|---|---|---|
| 資料（病人、醫囑…） | `localStorage`（`mock/db.ts`） | 所有分頁共用 |
| 誰登入了 | `sessionStorage`（`services/http.ts` 的 `setSessionUser`） | 只屬於這一個分頁 |
| 畫面是否鎖定 | `sessionStorage`（`setSessionLock`） | 只屬於這一個分頁；重新整理仍鎖定 |

- **資料要同步**：每個分頁在記憶體各握一份資料庫，寫入時整份寫回。若不同步，分頁 B 的下一次寫入會把分頁 A 剛建的病人蓋掉。所以監聽 `storage` 事件（只有**其他**分頁寫入才會觸發），收到就重新載入並通知頁面重新查詢。
- **登入身分刻意不共用**：展示時常一個分頁登入醫師、另一個登入藥師，並排看醫囑送到藥局。代價是在 A 分頁登入，B 分頁按 F5 仍是未登入（「複製分頁」會帶走一份當下的登入）。真實系統多半相反：憑證放在 cookie，所有分頁共用。

- **閒置鎖定，不是登出**（`services/idle-rules.ts`、`composables/useIdleLock.ts`、`components/LockScreen.vue`）：預設 15 分鐘沒有點擊、按鍵、捲動就鎖定畫面（管理員可在「系統管理 → 安全設定」改為 1–60 分鐘），鎖定前倒數提醒。直接登出會讓寫到一半的病歷消失，所以是鎖定：整個畫面蓋住，同一人輸入密碼回到原畫面、沒存的內容還在；換人使用按「切換使用者」才真正登出；密碼連錯 5 次強制登出。鎖定中服務層的 `requireUser` 一律拒絕（LOCKED，頁面不提示），直接呼叫 API 或按 F5 都繞不過；背後的元素設為 `inert`，Tab 也跳不到。計時用「最後操作時間＋現在時間」算，不靠倒數——背景分頁的計時器會被瀏覽器放慢、電腦睡眠會暫停，醒來一算就知道該鎖。各分頁登入各自獨立，所以也各自鎖定。

- **密碼**（`services/password-rules.ts`）：自己變更、管理員新增帳號與重設都用同一套規則（至少 8 碼、英文字母加數字、不可包含帳號、不可與目前相同；既有的 1234 照樣能登入，規則只管「設定新密碼」）。變更要輸入目前密碼（座位上沒登出的電腦，別人不能順手改掉密碼占用帳號）。管理員設定的密碼（新帳號、重設）本人登入後必須先改，改之前服務層 `requireUser` 一律拒絕（PASSWORD_CHANGE），不是只有畫面擋。每個分頁記下登入時間（毫秒），密碼變更後比變更時間早登入的分頁全部失效——密碼外洩時改密碼，就能把別人踢出去；改密碼的那個分頁則繼續登入。**期限與歷史**（`passwordAge`、`reusedPassword`、`checkPasswordPolicy`）：預設 90 天到期、不可重複最近 3 次（含目前這組），管理員在「安全設定」調整（期限 0＝不限）。期限從本人設定那天（`User.passwordSetOn`）算，到期前 14 天右上角提醒、帳號清單標出；過期**不鎖帳號**，和管理員設定的密碼一樣只能改密碼或登出（`requireUser` 擋，不是只有畫面）。期限用另一個日期欄位，不用踢分頁的 `passwordChangedAt`——種子若設那個，每次「重置展示資料」都會把管理員自己踢出去。以前的密碼只在服務層比對、不送到畫面；管理員重設前的舊密碼與給的暫時密碼都記進歷史（本人不能改回外洩的那組）。示範：`nurse02` 的密碼 80 天前設定（右上角「密碼 10 天後到期」），把期限改成 60 天就會過期。

- **權限只能「在規則內調整」**（`services/permission-rules.ts` 的權限目錄、`http.requirePermission`、`services/permission.ts`）：每個受控操作在目錄裡一筆——法規與醫療責任允許的角色（`candidates`，程式碼）、預設、是否固定、可否指定給個人。系統管理「權限」只能在範圍內勾選、至少留一個角色；固定的（開醫囑、給藥、發藥、收費、帳號與權限）不能改——把開醫囑勾給櫃台會出現沒有醫師的醫囑。主管型權限可以指定給個人（採購核准給藥劑部主管、優免核准給櫃台組長，取代以前的「可核准優免」帳號欄位）。調整要寫原因、寫稽核；會讓人失去權限的，先列出受影響的帳號再確認。**服務層、設定畫面、說明表格讀同一份目錄**：以前「主要操作權限」是手寫摘要，第一版就和程式不符；流程測試掃描原始碼，確認目錄每一項都有服務層在檢查、服務層檢查的都在目錄裡。登入資料帶 `can`（這個分頁能做哪些），頁面據此不顯示按鈕（`composables/useCan`），把關仍在服務層。
- **一個帳號多個角色，同一時間用一個**（`services/role-rules.ts`、`http.ts` 的 `sessionRole`）：帳號存 `roles`，每個分頁記一個「作業角色」（登入時選、右上角切換，不必重新登入）。服務層的 `requireUser` 回傳帳號加上作業角色，所以每條以角色寫的規則意思都不變——不採「所有角色的權限加總」，否則「護理師兼櫃台新增過敏，算誰登錄」「醫師兼管理員，『管理員不能臨床』還算不算」都變得模糊。帳號其實有那個角色、只是現在用別的角色時，錯誤訊息直接說「請切換為某角色」。稽核每筆都記下當時的角色。醫師＋藥師不可兼任（醫藥分業）。管理員拿掉某人正在用的角色時，那個分頁改用他剩下的角色並提示，不登出。

- **診間是主檔，不是自由輸入**（`schedule.saveRoom`）：每週門診表的診間只能從啟用中的診間選，已被同時段其他門診占用的列出來但不能選、寫明誰在用；服務層也檢查（以前打「2O1」就多出一間不存在的診間）。診間號建立後不能改；還有門診表在用的不能停用。位置印在掛號單上。

### 12. 替使用者擋下意外

- **對話框防誤關**（`components/ui/UDialog.vue`）：輸入或選擇過內容後，點背景、按 Esc 都不會關，只能按「取消」或 ×，醫囑、出院摘要寫到一半不會消失；沒輸入過的確認框照舊可以點背景關閉。
- **游標位置**：對話框打開時游標移到第一個輸入欄位，關閉時回到打開前的按鈕，鍵盤使用者不必按一堆 Tab。
- **按 Enter 送出，但不是每個對話框**：`UDialog` 綁了 `@submit` 才以 `<form>` 呈現，單行欄位按 Enter 送出、多行文字框按 Enter 換行。只給「送出後還能修改」的資料維護表單（進貨、盤點、帳號、主檔、排班、預防保健登錄…）；**開立醫囑、辦理出院、停診刻意不綁**——手還在輸入劑量時誤按 Enter 就開出一筆醫囑，這類動作必須明確按下按鈕。
- **能撤銷就不必先問**：停診通知的「已通知」要連續按幾十次，每次都確認只會讓人不看就按「確定」；改成按錯可以撤銷（撤銷才確認，因為少用）。
- **提醒，但由服務層判斷**：新增同名藥品不是錯誤（不同廠牌），但要提醒。流程是先送出 → 服務層查出同名回 `CONFLICT` → 頁面確認 → 帶 `allowSameName` 重送；其他欄位的錯誤會先回報，不會先問了同名才發現欄位沒填。使用者按「取消」時丟出 `Cancelled`（`composables/useService.ts`），`useAction` 安靜結束，不顯示錯誤。
- **盲盤要在服務層遮，不是畫面藏**：清點中，帳上數量、差異根本不出服務層（盤點單不給 systemQty；庫存清單、明細、補貨建議量、調劑單的庫存欄都回 0 並標出盤點單號）。只在畫面上藏，打開開發者工具就看得到；而且「可用天數」「偏低」標籤、補貨建議量都是用數量算的，一樣會洩漏，要一起遮。缺藥判斷（能不能核對）仍用真的數量——拿遮掉的 0 判斷會把有貨的藥擋下。
- **盤點期間照常發藥，差異以「清點那一刻」為準**：每填一批，服務層記下那一刻的帳上數量；過帳時差異套用到「現在」的帳。拿建立盤點單時的帳來比，盤點期間發出去的藥會全部變成盤虧。清點後那一批又被發光、帳上不夠扣盤虧時，整張不過帳，請退回重盤。
- **連續輸入的存檔要排隊**：盤點表一列填完按 Enter／Tab 馬上下一列。以前共用一個 `useAction`（進行中就忽略新的呼叫），上一列還在存時下一列的存檔被吞掉——數字留在格子裡，其實沒存。改成排隊依序送、每列顯示「儲存中」，送出前先等所有存檔完成。
- **不合法的輸入不拿來計算**：盤點輸入 -3 時，以前同時出現錯誤和「差異 -23（盤虧）」。輸入不合法就只顯示錯誤，不顯示差異、確認鈕停用，Enter 也送不出去。
- **發藥前確認領藥的是誰**：按「發藥」要輸入病人說出的出生月日（4 碼，服務層比對），或勾「他人代領」登記代領人與關係；兩種都記在調劑單與稽核。生日在病人資料列上本來就看得到——這一步的用意是逼藥師真的開口問。
- **一鍵做完，但把關不省略**：門診「完成並叫下一位」（Ctrl+Enter）把三個動作合成一個，過敏、劑量確認照樣跳出；任何一步沒成功（按了取消、缺診斷、服務層擋下）就停在原病人，不會往下叫。快速鍵只在看診中可編輯時有效。
- **搜尋時 Enter 直接選取**：藥局、批價清單只剩一筆符合時，Enter 就選中並切到它所在的分頁。藥局的 1–3 位數字只比對領藥號——否則打「4」連病歷號含 4 的人都找出來，就選不到唯一一筆。
- **窄螢幕捲到明細**（`composables/useRevealOnNarrow.ts`）：手機上左右兩欄變成上下堆疊，點清單後明細出現在畫面外，使用者以為沒反應。選取改變時把 `data-detail` 區塊捲進畫面；寬螢幕兩欄並排時不動作。

### 13. 資料版本號

`mock/db.ts` 的 `SCHEMA_VERSION` 一變，瀏覽器裡的舊資料會自動重建。

- **要調**：結構不相容地改變（新增必要的資料表），或種子資料的內容改變。
- **不用調**：只新增選用欄位，舊資料缺少它也能正常運作。
- **一定最後才調**：開發伺服器在版本號改變的當下就會重建資料，先調版本號再改種子，就會得到「新版本號＋舊內容」的資料。

### 14. 錯誤要指到欄位，而且一次說完

「改一個、送出、再冒出下一個」是表單最惱人的體驗；只在頂端說「請填寫報告內容」而不標出是哪一格，也一樣。

- **`failFields(errors)`**（`services/http.ts`）：一次丟出多個欄位錯誤，`ServiceError.fields` 帶著全部，`useAction` 把它放進 `fieldErrors`，每個欄位底下各自顯示。只有一個欄位時用 `failField`。
- **`fieldErrors()` 收集器**：必填、格式、範圍先全部收集，`done()` 一次回報；**欄位都對了才檢查規則**（重複、同名、停用前影響），因為規則常常要依賴欄位已經正確。同一欄位只留第一個錯誤（效期空白時只說「請輸入效期」，不再接著說「效期已過」）。
- **純規則函式回傳錯誤物件，不直接丟出**：`checkPreventResult` 回傳 `{ 欄位: 訊息 }`，服務層交給 `failFields`，頁面也能拿來即時提示。
- **要不要一起報，看規則本身**：補登預防保健報告時，每個結果都要填報告，所以「沒選結果」和「沒填報告」一起標出；新登錄時可選「待報告」（不用填欄位），沒選結果就只標結果——先標欄位會誤導。
- **訊息先說怎麼辦**：匯入不完整的檔案時說「這不是完整的匯出檔，請使用本系統「匯出資料」產生的檔案」，缺少的資料表名稱放第二行、最多列 5 個給工程人員查；以前一口氣列出約 40 個英文表名。

### 15. 列印

收據、藥袋、日結報表、掛號單都用瀏覽器列印，規則在 `style.css` 的 `@media print`：

- **只印 `.print-area`**：無關的元素 `display: none`（不佔空間）；列印區塊的上層（版面、捲動區、對話框）用 `:has(.print-area)` 改回一般排版，拿掉 `fixed`、`overflow`、限高。以前用 `visibility: hidden` 加絕對定位，藥袋超過一頁就被截掉、收據外框被拉到頁尾。
- **內容多就自然分頁**：日結報表 60 筆印成 3 頁；藥袋每張固定高度（`print:h-[134mm]`，兩欄兩列，A4 一頁 4 張），不會一張跨兩頁（實測 3／8／9／15 張分別印成 1／2／3／4 頁）。
- **匯出和列印用同一份報表**：CSV 由服務層的純函式 `dailyReportCsv`（`services/report-csv.ts`）從畫面上那份報表產生，頁面只負責下載——畫面、紙本、Excel 的數字不會各算各的。開頭加 BOM（Excel 才不會把 UTF-8 中文開成亂碼）；以 `= + - @` 開頭的文字前面加 `'`，病人姓名不能變成 Excel 公式（CSV 注入）；合計列的名稱不和明細的「類別」同名，篩選時不會混進來。
- **紙本要能追溯**：日結報表的表頭印出報表日期（區間報表印期間）、**列印時間與列印人**——同一天印兩次數字不同時，查得出哪張是何時誰印的。列印時間在按下「列印」那一刻取值。
- **藥袋**（`pharmacy/components/DrugBagLabels.vue`）：藥師法規定的欄位都印——藥局名稱地址電話（`utils/hospital.ts`，收據、掛號單、日結共用）、病人姓名性別年齡、藥名規格、用法劑量、天數總量、**作用、注意事項**（藥品主檔必填，管理員新增藥品沒填會被擋）、**服用時機**（藥品主檔欄位：飯前、飯後、隨餐、空腹、皆可，`drug-rules.timingText`；以前一律印「飯後」，Omeprazole、Levothyroxine 都印錯。醫師可在處方列的時機選單為這張處方另外指定，藥局處方表標「醫師指定」；示範：內科糖尿病追蹤的 Metformin 隨餐改飯後）、處方醫師、**調劑藥師**（核對的人；還沒核對就先印的話是目前登入的藥師）、調劑日。一張 1/4 A4，用最長的警語實際列印過，4 張一頁、沒有被裁掉。
- **掛號單**（`components/RegistrationSlip.vue`）：80 mm 寬（櫃台出單機），印診間與位置、看診號、就醫序號、預估應收，和病歷號的 Code 39 條碼（`utils/code39.ts`，SVG）。條碼掃描器就是「打字＋Enter」，批價、掛號的搜尋框掃了就直接選到這位病人；條碼畫出來後再反向解碼驗證過。
- **用真的列印驗證**：頁數是用無頭 Chrome 的 `Page.printToPDF` 實際產生 PDF 算出來的，不是看預覽畫面估的。

### 16. 把要做的事送到使用者面前

這一輪對照原系統（jian-HIS，比較與取捨見 `docs/jian-his-comparison.md`），逐一檢查「每個角色在自己的工作上要找多久」。原則是：使用者需要的資訊，在他做事的那個畫面上就看得到，不必換頁、捲動或自己記。

- **櫃台**：確認掛號區顯示預估應收（看完診才收錢，但要答得出「今天多少」）；病人卡上直接退掛、改期；停診待通知在掛號頁就有提示條，首頁有待辦。
- **護理師**：沒選病人時就是全病房「本班待辦」；醫師新開、停止的醫囑在病人清單上標「新醫囑」，核對後才消失；「醫囑」分頁列出長期的護理、飲食、處置醫囑（以前護理端看不到「翻身 Q2H」「禁食」）。
- **醫師**：組套一鍵帶入（個人＋科室共用）、片語簡碼展開；預防保健在看診頁就能登錄，已量的血壓身高體重帶入。
- **醫師叫號時，上一位還沒完成會先問**（`opd.startConsult`）：「第 2 號 楊佩珊（08:07 叫號）還在看診中」，可以「回到第 2 號」或「仍要叫號」（病人去檢查、等報告時先看下一位）。不硬擋；仍要叫號的寫進稽核，候診清單標「同時看診」。以前不提醒，前一位的病歷停在草稿、批價永遠等不到他。
- **藥師、批價**：清單可搜尋，批價清單直接顯示預估應收；日結列出看完診還沒批價的人。
- **帳本寫入不對外**：`postStock`（庫存唯一的寫入點）本身不檢查登入與權限，它是給進貨、發藥、盤點過帳這些已經檢查過的服務呼叫的。以前它從 `inventory.ts` 匯出，`overNetwork(inventory)` 就把它一起包成 `inventoryApi.postStock`——任何頁面都能直接改庫存。現在放在不對外的 `stock-ledger.ts`，流程測試檢查各 Api 都沒有它。**模組裡 export 的每一個函式都會變成 API**，內部用的工具不要放在對外的服務模組裡。
- **需求要算在「需要的地方」**：補貨申請是窗口缺藥、病人在門診藥局等。以前不分地點，大型醫院藥庫一到貨申請就結案，首頁不再提醒，病人在窗口還是領不到。現在只有藥進了門診藥局才沖銷（大型醫院要等撥補簽收）。
- **運送中是一個狀態，不是一個地點**：撥發時藥庫就扣、簽收時藥局才入，中間的藥不屬於任何地點（全院總量暫時少了運送中的量，庫存頁另外標「運送中」）。簽收逐批填實收、短少寫原因——全院總量最後只少了真的不見的部分，查得到是哪一張單、為什麼。
- **一般進貨走採購單，「無單進貨」要原因**：開單與核准分開（藥師開、管理員核准），到貨對品項入庫、超收擋下；緊急調貨、贈品、退藥回收這些不經採購的入庫，選原因後異動帳標「無單進貨：原因」，月底對帳查得到。
- **缺藥時，窗口只「申請補貨」**（`inventory.requestRestock`）：以前窗口的「補貨」直接開進貨單，病人在窗口等，藥師得憑空編一個批號、效期，建議量固定「缺量＋500」。現在窗口只填數量（建議量依用量算、附算式），調劑單標「已申請補貨」；同一種藥同時只有一張待到貨申請，再缺就追加、把病人加進等候名單。申請是「需求」：開採購單時勾選帶入，貨到了在採購單「到貨入庫」，入庫量自動抵掉申請（分批到貨會留著尚欠），到齊結案，等候的單就能核對。首頁有「補貨申請待到貨」待辦。
- **執行仍回到原本的畫面**：待辦清單、提示條只負責「帶過去」，給藥、核對、登錄都在原本的頁面做——把關（高警訊雙人核對、原因填寫）只寫一份。

## 已知的簡化與限制

這是展示系統，以下是刻意的簡化：

- **密碼過期不鎖帳號**：過期的人登入後先改密碼就能用，沒有「過期太久要找管理員」；以前的密碼和目前的密碼一樣以明文存在瀏覽器（真實系統只存雜湊）。
- **沒有真正的後端與資安**：密碼以明文存在瀏覽器，登入頁會列出展示帳號，匯出檔也包含密碼。權限檢查在前端的模擬服務層，可以被繞過。
- **健保規則為簡化版**：掛號費、部分負擔、預防保健資格只取主要條件，並非完整法規。
- **藥車交接只到「逐盒點收」**：沒有病房點班（病房常備沒有自己的存量，沒東西可點）、沒有藥車簽收單列印；點收不擋給藥。送回藥局只記誰、何時送回，數量以藥師點收為準。無法逐劑換算的藥（胰島素筆）整支發、不退。病房常備沒有自己的存量（帳在住院藥局）。
- **庫存地點沒有權限分開**：藥師都能維護地點、改負責地點（真實醫院可能只有藥劑部主管能改）；藥庫同時只能有一個（撥補、退回藥庫都找那一個）。
- **退回藥庫是送了才決定**：藥局送出就扣帳、運送中，藥庫簽收時才拒收（藥要再送回去），沒有「先申請、藥庫同意才出貨」；待報廢區只收退回的藥，藥庫自己發現的過期品照舊用「報廢過期」。報廢沒有雙人覆核。
- **供應商主檔只有基本資料**：名稱、統編、聯絡人、電話、備註；沒有付款條件、合約價、供應商可供應的品項清單（任何供應商都能買任何藥）。進價只記在採購單上，不做庫存成本計價、不產生應付帳款；「以前的進價」只算核准訂購過的單。
- **盲盤只遮藥師端**：醫師開藥選單的「可用量」照常顯示（醫師不參與清點）。
- **權限是程式設定**：角色與可做的事寫在程式碼中，系統管理頁只能檢視，不能勾選調整（原因寫在權限頁）。
- **稽核紀錄只保留最近 500 筆**（受瀏覽器儲存空間限制），「最近登入」也取自這裡。
- **藥品中文名是展示用譯名**：用通用的中文學名，不是衛福部核定的正式譯名；不收錄商品名（「普拿疼」這類習慣叫法放在只供搜尋的別名）。
- **病房用餐時間全院一套**：住院給藥依服用時機對齊早 07:30、午 12:00、晚 17:30，不能依病房或病人（例：洗腎病人改時段吃飯）調整；護理師要提早或延後給，照現有規則在給藥時間窗內給或寫原因。住院醫囑的服用時機開立後不能改，要停掉重開。
- **Chrome 無痕視窗關閉後資料就消失**：無痕模式下一切功能正常，但瀏覽器在視窗關閉時清掉儲存的資料。網站無法可靠地偵測無痕模式，所以沒有提示。（儲存空間已滿、或瀏覽器完全不允許儲存時，畫面上方會一直顯示警告，並說明是哪一種原因。）
- **優免主管核准只有當場核准**：沒有「先送簽、主管在自己的畫面核准」的流程，也沒有限制連錯幾次（每次失敗都寫稽核）；掛號頁的預估應收不含優免（優免在批價時才決定）。
- **權限第一版只涵蓋 15 項操作**：其他動作仍是程式裡寫死的角色（`requireUser`）；頁面能不能進入照路由固定；「停診、代診」固定給管理員（排班只在系統管理頁，櫃台沒有畫面，開放給櫃台組長要先把停診搬到掛號頁）。
- **掛號預收是選填、整筆的**：掛號時可以先收一筆（預設預估應收），批價扣抵、多退少補；沒有欠卡押金，預收款也不能轉給別次就醫用。錢不夠可記欠款（只限現金）。退費只能整張退（沒有「只退某個自費項目」），退款依原付款方式、不能改用別的方式退。
- **只有長期給藥醫囑能「修改」**：劑量、頻率、途徑、服用時機可以改；換藥、臨時醫囑、護理／飲食醫囑請停止後另開。修改在資料上仍是停止與新開兩筆。
- **片語沒有全院共用、也沒有組套快捷鍵**：只有個人、科室（醫師）、病房（護理師）三種範圍；護理站「補記反應」那一行小欄位不展開片語。病房共用片語跟著「目前所在的病房」，帳號沒有綁定所屬病房。
- **報表區間最多 31 天**：再長要分段查詢、分段匯出；匯出是 CSV（Excel 可開），不是 .xlsx。
- **會診只在住院、看摘要**：會診醫師看的是會診單附上的病人摘要，不能打開完整病歷、也不能開醫囑（要處置就由主治依建議開、或轉科）；沒有門診會診、沒有會診費。新科只能整筆接受或婉拒轉科。轉床只能選空床。
- **處方箋有效期只提醒不擋**：逾期的單在藥局清單標「處方逾期」、調劑單上方有提醒，照常可發（是否請醫師重開由藥師判斷），發藥稽核註明「處方已逾有效期」。慢箋每次調劑也套同一個 3 日規則（從登記領藥那天算），沒有另外處理。
- **調價沒有記錄健保發文號**：藥價、醫令點數、掛號費、部分負擔都有生效日，但只記誰、何時設定；部分負擔是整組參數一起排定（不能只排其中一項的日期）。就醫身分的「免部分負擔」「自費身分」是分類，改了立即生效。
